# M12 — Role-aware per-stem FX routing

## Intent

M12 brings M11's editable processing chains into the generated-project workflow. Each generated stem can have an independent insert and independent send levels to shared effect returns. Routing is an offline post-generation pass: the original float32 stem buffers remain unchanged, no composition random streams are consumed, and stem-only regeneration remains deterministic.

The musical design follows the IDM guides' attention hierarchy and orchestration principles: roles can be processed independently, while selected layers can fuse through a shared space or echo return. Independence is selective; the default routing is dry and every send is opt-in.

## Signal flow

For each stem:

`dry stem → optional serial insert → post-insert sends`

The direct output is kept as a separate aligned stem. Sends from multiple stems are summed into shared buses:

- **SPACE:** shared restrained-space return, intended for depth and perceptual fusion.
- **ECHO:** shared tape-echo return, intended for rhythmic replies, interlocking, and selected punctuation.

The returns are summed at the master, not written into the dry stem files. Mute/solo affects direct stem audibility and bus contributions. Gain and pan remain mixer controls and do not cause the offline effects pass to rerender.

## Stem Mixer workflow

1. Generate a composition and open **STEM MIXER**.
2. In **ROLE-AWARE FX ROUTING**, choose a stem.
3. Select BYPASS or one of the M10/M11 starter chains as that stem's insert.
4. Set the insert wet level and SPACE/ECHO send amounts.
5. Set each shared bus processor, return level, and tail duration.
6. Audition through the existing master preview. Routing changes invalidate the offline processing cache; ordinary fader, pan, mute, and solo changes do not rerender inserts.
7. Export the project. The export retains dry stem WAVs and includes fx_routing.json, shared return WAVs under returns/, the routed master.wav, and mix.json provenance.

Routing is dry by default. The base generator and ordinary project generation do not require Pyo. Pyo is loaded only when an active insert or send bus must be rendered.

## Portable routing schema

Schema version 1 stores a route record for each stem and two bus records. A minimal document is:

```json
{
  "schema_version": 1,
  "master_wet": 1.0,
  "stems": {
    "kick": {
      "insert": {"kind": "bypass"},
      "sends": {"space": 0.0, "echo": 0.0}
    },
    "hats": {
      "insert": {
        "kind": "preset",
        "preset": "digital_fracture",
        "wet": 0.35,
        "tail_seconds": 1.5
      },
      "sends": {"space": 0.12, "echo": 0.08}
    }
  },
  "buses": {
    "space": {"chain": "restrained_space", "wet": 0.28, "tail_seconds": 2.0},
    "echo": {"chain": "tape_echo", "wet": 0.32, "tail_seconds": 1.5}
  }
}
```

All current project stem names must match the names in the file. Missing stems receive bypass/zero-send defaults; unknown stem names, invalid ranges, unknown bus names, and unsupported schema versions are rejected. Insert presets reuse the M10/M11 chain registry. A chain can also be represented by a custom ordered stages list.

## CLI

Create a starter routing document for an exported project:

```powershell
reawarp-routing output/my-composition --output output/routed
```

Validate a saved routing file without requiring Pyo:

```powershell
reawarp-routing output/my-composition --routing output/routed/fx_routing.json --validate
```

Render a routed project:

```powershell
reawarp-routing output/my-composition --routing my-routing.json --output output/routed
```

The CLI reads the dry stem WAVs from the project directory and writes processed stem copies, shared return WAVs, and a routed master to a separate destination. It does not overwrite its source project.

## Processing semantics and limitations

- Inserts are serial M11 chains or M10 presets.
- Sends are post-insert and feed shared stereo buses.
- Returns are parallel to the direct stems.
- Direct stem outputs remain frame-aligned. Insert tails are preserved on send paths; shared returns and the final master can extend beyond the source frame count. Dry stem WAVs are still exported at the original project length.
- The implementation is intentionally minimal: two fixed shared buses, no arbitrary user graph, no external file-path references inside routing JSON, and no send-to-send routing.
- The initial UI selects starter presets for insert and bus chains. A custom ordered stage list can be embedded directly in routing JSON with kind stages; external file paths are deliberately not stored in the routing document.
- The routing editor handles inserts and sends; M11 FX Lab remains the detailed serial-stage editor.

## Conservative role-combination audition matrix

These are restrained starting values for a listening pass, not results from a subjective audition. All send values are linear 0–1 controls. Keep the kick dry and raise one family at a time before combining them.

| Listening pass | Kick / snare | Hats / break | Melody | Ambience | SPACE return | ECHO return |
|---|---|---|---|---|---:|---:|
| Percussion focus | dry / 0.00 | 0.06 space, 0.02 echo | off | off | 0.12 | 0.05 |
| Melody foreground | dry / 0.00 | 0.02 space, 0.00 echo | 0.08 space, 0.04 echo | off | 0.14 | 0.08 |
| Ambience background | dry / 0.00 | off | off | 0.16 space, 0.00 echo | 0.16 | 0.00 |
| Combined roles | dry / 0.00 | 0.04 space, 0.01 echo | 0.07 space, 0.03 echo | 0.12 space, 0.00 echo | 0.14 | 0.06 |

Use the same bus processor while comparing these passes. Compare the dry master, each role in isolation, and the complete mix at matched playback levels. The shared return should be audible as a common environment, not as a second foreground source. Reduce the return before changing the source roles if the mix loses attack definition or melodic intelligibility.

An objective check can report the return-to-direct RMS ratio and peak headroom for each pass, but those measurements cannot decide whether the shared space masks a phrase or whether an echo is musically distracting. The final evaluation still requires listening on the target playback setup.

## Validation and status

The smoke workflow compiles the package, exercises routing normalisation and portable JSON validation without Pyo, runs the existing CLI/library smoke checks, and instantiates the desktop UI offscreen. No unit-test suite is reintroduced.

Pyo audio rendering and listening still require validation on the target Windows environment. Routing metadata/JSON checks do not prove the subjective audio result.

## Deferred

- Tempo maps across changing meters; constant-BPM delay sync and beat automation are implemented in M13.
- Pre-fader/post-fader send selection and user-defined bus graphs.
- Parallel insert branches and multiband routing.
- Sidechain interaction and a modulation matrix.
- Async background processing and incremental cache invalidation at bus/stem granularity.
- Master bus insert chain and loudness metering.


## M22 routing contract update

M22 supersedes the v1 dry-by-default routing editor behavior. Routing schema v2 retains this document's fixed SPACE/ECHO model, adds role-derived automatic defaults, explicit pre/post insert and fader send taps, wet-only auxiliary returns, route meters, tail reporting and cancellable background rendering. Version 1 routing documents remain readable and are migrated in memory to manual v2 routes without changing authored values. See [M22 — Mixer and routing quality](M22.md) for the current signal and gain laws.
