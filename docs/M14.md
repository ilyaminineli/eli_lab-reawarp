# M14 — Reliability and Performance Baseline

**Started:** 2026-11-24  
**Status:** In progress — portable regression and Windows CI coverage implemented; target-machine profiling remains pending.  
**Scope:** regression tests, signal diagnostics, reproducible benchmarks, stage timing, and a modular project-centred desktop shell.

M14 stabilises the existing organism before adding further synthesis, composition or DSP systems. It protects the integration between form planning, event generation, instrument rendering, stems, processing and audition rather than testing each module only in isolation.

## Implemented

### Signal diagnostics

`reawarp.diagnostics` provides non-destructive analysis of mono and channel-last audio buffers:
- frame count, channel count, duration and optional expected-frame validation;
- peak, RMS, dBFS and crest factor;
- finite/non-finite and over-full-scale sample counts;
- per-stem frame alignment.

These measurements identify engineering problems; they do not score musical quality or substitute for listening.

### Deterministic regression coverage

The pytest suite now covers:
- stable root-seed and named-stream derivation, plus lane independence;
- deterministic, contiguous section plans and phrase-aware drum arrangements;
- signal diagnostics and non-mutation;
- dry-default FX routing, source-buffer immutability, and beat-automation envelopes;
- repeatable small renders, finite samples, aligned stems and bit-identical stem-only regeneration;
- break-transform short/empty/stereo inputs, deterministic processing, duration boundaries and source immutability;
- exact score JSON round trips and MIDI note, event-provenance, tempo, meter and automation interchange;
- exported-project reopen validation, including configuration, event records, PCM stems, frame alignment and score metadata;
- nested workspace registration and navigation transitions in the offscreen desktop UI.

### Exported project round trip

A complete project export can be reopened with `ReawarpProject.load(directory)`. The loader validates the project/event schema versions, configuration, recorded duration and frame count, stem names, PCM sample rate and alignment, finite samples, and the accompanying score metadata. It preserves each stem as channel-last float32 audio. It rejects partial exports that do not include source stems; it does not silently reconstruct missing audio.

The PCM reader supports standard 8-, 16-, 24- and 32-bit integer WAV data without downmixing channels.

### Benchmark harness and engine timing

Run a reproducible baseline from the repository root:

```powershell
python scripts/benchmark_generation.py --durations 5 30 180 --palettes subtractive fm --sample-rate 48000 --output benchmark-m14.json
```

The report records platform/Python version, total wall time, real-time factor, allocation peak, optional RSS observations, event/stem counts, engine timing metadata and per-stem signal diagnostics. Engine metadata separates composition planning, event generation, synthesis/buffer rendering, headroom management and total engine time.

### Project-centred desktop shell

The former flat row of top-level tabs is replaced with a collapsible grouped workspace navigator:
- **Compose:** Generator and Break Lab.
- **Produce:** Stem Mixer and FX Lab.
- **Assets:** Library.

A persistent project-context header and shared audition transport keep the workspaces connected to the current project/session. The navigator is data-driven and supports arbitrary group depth. FX Lab and the stem-mixer editors use separate scroll regions; empty states explain why a project or audio is not yet available.

### Windows CI

The GitHub Actions workflow retains its Python 3.10–3.12 Linux matrix and adds a native Windows regression job on Python 3.11. The Windows job installs the supported desktop/audio/MIDI extras, runs the full pytest suite with Qt's offscreen platform, compiles the package, and smoke-tests the CLI and short benchmark.
