# M14 — Reliability and Performance Baseline

**Started:** 2026-11-24  
**Status:** In progress  
**Scope:** regression tests, signal diagnostics, reproducible benchmarks, stage timing, and a modular project-centred desktop shell.

M14 stabilises the existing organism before adding further synthesis, composition or DSP systems. It must protect the integration between form planning, event generation, instrument rendering, stems, processing and audition rather than testing each module only in isolation.

## Implemented in this increment

### Signal diagnostics

`reawarp.diagnostics` provides non-destructive analysis of mono and channel-last audio buffers:
- frame count, channel count, duration and optional expected-frame validation;
- peak, RMS, dBFS and crest factor;
- finite/non-finite and over-full-scale sample counts;
- per-stem frame alignment.

These measurements identify engineering problems; they do not score musical quality or substitute for listening.

### Deterministic regression coverage

The new `tests/` suite covers:
- stable root-seed and named-stream derivation;
- independence between named random streams;
- deterministic, contiguous section plans;
- signal diagnostics and non-mutation;
- dry-default FX routing and source-buffer immutability;
- beat-addressed automation and invalid target/point rejection;
- small deterministic renders, finite samples, aligned stems and stem-only regeneration invariants.

### Benchmark harness

Run a reproducible baseline from the repository root:

```powershell
python scripts/benchmark_generation.py --durations 5 30 180 --palettes subtractive fm --sample-rate 48000 --output benchmark-m14.json
```

The report records platform/Python version, total wall time, real-time factor, allocation peak, optional RSS observations, event/stem counts, engine timing metadata and per-stem signal diagnostics. The short CI invocation uses a 5-second render; the 30- and 180-second cases should be run locally on the target Windows machine.

### Engine timing metadata

Each generated project records elapsed time for composition planning, event generation, synthesis/buffer rendering, headroom management and total engine time. This metadata helps identify the phase that should be profiled next; it is not a substitute for a statistical benchmark.

### Project-centred desktop shell

The former flat row of top-level tabs is replaced with a collapsible grouped workspace navigator:
- **Compose:** Generator and Break Lab.
- **Produce:** Stem Mixer and FX Lab.
- **Assets:** Library.

A persistent project-context header and shared audition transport keep the workspaces connected to the current project/session. The navigator is data-driven and supports arbitrary group depth, so future sub-workspaces can be registered under paths such as Compose / Generator / Advanced without turning the main window into a long tab strip. FX Lab also uses a vertical scroll container so its ordered chain editor and dry/processed comparison remain reachable on compact screens.

The Stem Mixer now presents a deliberate empty state until a composition exists, rather than exposing a large, mostly unusable routing surface with no project loaded. Its stem matrix and routing/automation editors have separate scroll regions so one cannot make the other inaccessible. Generator and Break Lab use splitter-based layouts and avoid horizontal control clipping. Blank waveform and spectrogram areas now show contextual empty states instead of unexplained empty graph grids.


## IRO ecosystem and phrase grammar extension

The application now has an explicit IRO integration layer. `reawarp.samples.iro` reads the local IRO drum index/map, sound-lab, sound-FX and eight mathematical-entity manifests. It exposes original pack-relative paths, role/family/articulation, sample-rate/duration, optional SHA-256, source feature index and seed. It rejects pack-root path traversal and can verify supplied hashes without modifying assets. The current checkout has no `.wav` payloads under `samples/Iro`, so these are metadata/index-only records for now; the Generator filters them out of playable selectors and the Library labels them `INDEX ONLY · WAV MISSING`. Event/project metadata preserve the source identity.

The composition director now includes IRO metamorphosis, uplift/drop/return and two-movement structures. A phrase-directive pass maps each section to a compositional function and role activity (kick, snare, high percussion, melody, texture and ambience), and the offline engine applies those activity values while keeping the independent deterministic role streams. Drop and void are distinct: a drop removes the principal low anchor but leaves fragments/residue; a true void suppresses active voices and leaves space for ambience.

See [IRO integration](IRO_INTEGRATION.md). The current generated-kit index exposes 96 drum entries, and the entity manifests expose 48 variants. The Library can inspect those plus sound-lab and sound-FX metadata, but actual audio audition/rendering awaits the WAV payloads. The current Generator's role selector is scaffolding for the future kick/snare/closed-hat playable sample lanes; it does not claim those files are currently available.

## Validation

The CI workflow runs pytest, existing command-line/FX/library smoke checks, an offscreen desktop construction check, and a short generation benchmark. Pyo audio rendering remains an optional target-environment check because it requires the native optional backend and critical listening.

## Acceptance policy

M14 is complete only when the regression suite and benchmark have been run on the supported target environment, any discovered regressions are fixed, and measured performance/memory results are recorded. Adding files and CI steps alone does not complete the milestone.
