# M22 — Mixer and routing quality

**Status:** Implemented on main — automatic role routing, portable v3 semantics (v1/v2 migration), four send taps, stage audition, meters, wet-only returns, tail/latency reporting, matched-level audition copies and cancellable background caching are integrated. Target-Windows/Pyo listening remains an experimental sign-off.

**Depends on:** M12/M13 routing and automation; benefits from M18 and M21.

## Design decision: effects are part of role routing

A new project no longer starts with every route bypassed and every send at zero. The desktop Stem Mixer, CLI no-routing-file path, and direct `render_fx_routing(..., routing=None)` API all use `role_aware_fx_routing()`. The automatic role assignment is the default; users only need to edit exceptions. The explicit `default_fx_routing()` helper remains a deliberately dry A/B/reset baseline.

| Musical role | Default insert | SPACE send | ECHO send | Intent |
|---|---|---:|---:|---|
| Kick / sub / bass | Bypass | 0.000 | 0.000 | Protect low-end anchor and transient |
| Snare / clap / rim | Restrained space, 0.08 wet | 0.050 | 0.015 | Short shared room and restrained punctuation |
| Hats / cymbals | Digital fracture, 0.07 wet | 0.055 | 0.020 | Light texture and small rhythmic reflections |
| Break / loop | Digital fracture, 0.10 wet | 0.040 | 0.020 | Blend the break without flattening its attack |
| Melody / lead / arp | Metallic machine, 0.07 wet | 0.075 | 0.035 | Separate foreground from the drum bed, add sparse replies |
| Texture / noise / drone | Restrained space, 0.10 wet | 0.100 | 0.010 | Put continuous material behind foreground events |
| Ambience / pad | Bypass | 0.035 | 0.000 | Reuse a little shared room, avoid echo on an already-wide bed |
| Unknown role | Bypass | 0.000 | 0.000 | Do not guess an identity from an unknown stem name |

These are deliberately conservative starting values, not a universal mix or a claim that the effect choices have been subjectively approved. The classifier is deterministic and inspectable. The user can override every insert, send, tap and return. **AUTO ROLE ROUTING** restores the role map; **RESET DRY** restores the explicit bypass baseline for matched A/B. Loading an old routing file preserves its manual values.

This is not a post-master effect. Each stem gets its own insert before the shared mixer. Sends are taken from a declared point on that stem and feed the fixed SPACE/ECHO auxiliary returns. The returns are summed with the direct/insert stems before the master output stage. No arbitrary graph or feedback loop is introduced.

## Signal semantics

### Per-stem path

`dry source → (optional serial insert) → direct stem`

The direct output uses a linear dry/wet crossfade:

`direct = dry × (1 − insert_wet) + insert_output × insert_wet`

A bypassed or zero-wet insert does not initialise Pyo. Insert tails are retained on the direct signal and can also feed post-insert sends. Dry source arrays and project stem files are never modified.

### Four send tap points

Each SPACE/ECHO send chooses one of four tap points, independently per stem and bus:

| Tap | Signal sampled | Fader gain/pan | Mute/solo gate |
|---|---|---|---|
| `pre_insert_pre_fader` | Original dry stem | No | Yes |
| `pre_insert_post_fader` | Original dry stem | Yes | Yes |
| `post_insert_pre_fader` | Inserted stem, including insert tail | No | Yes |
| `post_insert_post_fader` | Inserted stem, including insert tail | Yes | Yes |

Send amount is a linear contribution (0–1). A pre-fader send ignores gain/pan, but explicit mute and non-solo exclusion still gate it. A post-fader send receives the current gain and balance pan. The tap choice is part of the portable routing file, not an event-by-event annotation.

### Shared returns and master

- A send contribution is summed into one of the two fixed auxiliary input buffers.
- The SPACE/ECHO processor renders its return from that bus input. Return wet is applied to the processed return only; the dry contribution already remains on the direct path and is not duplicated in the aux return.
- The return starts at frame zero, aligned with its bus input. The built-in offline processor has a declared zero added algorithmic latency in this routing contract; musical delay time is an effect, not a compensation offset.
- Insert output tails and return tails propagate by extending the appropriate render buffer. The final master is extended to the longest direct/insert/return buffer; dry source files remain at their original source length.
- Master peak protection is applied after summing. The master meter records the final output.

### Gain staging

| Control | Law |
|---|---|
| Insert wet | Linear dry/wet crossfade from 0 (dry) to 1 (fully inserted output) |
| Send level | Linear contribution from 0 to 1 at the selected tap |
| Stem fader | Linear gain; UI 0–200% maps to 0–2 |
| Pan | Balance pan; centre is unity on both stereo channels; hard pan attenuates the opposite channel |
| Bus return wet | Linear gain on the wet-only return |
| Master wet | Final master gain from 0 to 1 |

No hidden normalization is applied to the source stems or individual sends. The master guard limits the summed result to the declared -1 dBFS ceiling. Routing diagnostics record boundary peaks and RMS values so gain changes can be reviewed.

## Portable schema v3 and migration

Routing JSON is now schema version 3. Version 1 and v2 files remain readable and are normalised in memory as manual routes with their historical send levels, insert bypass/preset state, fader values and default `post_insert_post_fader` taps. Saving an old file writes v3. A v3 route includes a derived `role` field for inspection; it never overrides an authored insert, send, tap or fader value. No stem name or control value is inferred from old metadata.

A v2 stem record contains:

- `insert`: bypass, preset or embedded ordered stages, with wet and tail duration.
- `sends`: independent SPACE/ECHO linear levels.
- `send_taps`: the four named tap choices.
- `gain_db`, `pan`, `mute`, `solo`: portable mixer state.
- `role`: inspectable classification derived from the stable stem identifier; `routing_mode`: `manual`, `role_auto`, or one of the role audition profiles.

Bus records contain processor chain, return wet, tail duration, ECHO delay division and `alignment_policy="start_aligned"`. Unsupported alignment policies, unknown buses/stems, invalid ranges and unsupported schema versions are rejected.

Routing schema v3 does not change M13 automation schema v1. Existing beat lanes continue to target insert wet, per-stem sends and bus wet; the same Score AutomationControlBus or legacy automation adapter drives their envelopes.

## Audition and observability

The editor can audition the following signals from the same routing render:

- Direct dry source
- Insert output
- Each per-stem SPACE/ECHO send contribution
- SPACE return
- ECHO return
- Master output

The editor shows peak, RMS, crest factor and headroom meters for direct, insert, sends, returns and master. It also reports return-tail duration and the start-alignment/latency policy. Meters are signal diagnostics, not judgements of artistic quality.

**MATCH LEVEL** is enabled for audition by default. It creates a separate copy aimed at -18 dBFS RMS, subject to a 0.95 peak ceiling. If the peak ceiling prevents the RMS target, the report says so. The production master, routed stem copies and source files are never level-matched or modified by this audition function.

The CLI role audition matrix exports the normal master and an additional `master_matched.wav` for each profile, plus the level-match gain and measured output in `render.json`. Compare snapshots at matched level, then listen again to the unmodified production master.

## Preview, export and asynchronous ownership

The GUI routing pass runs through a dedicated cancellable worker, not the GUI thread. It receives copies of the immutable dry source buffers and snapshots of routing, fader state, tempo and automation. Cancellation is cooperative at safe boundaries between stems, buses and expensive processor calls. A running Pyo call itself is not forcibly interrupted; cancellation is observed as soon as that call returns.

Results are copied into an owned cache keyed by project revision, routing JSON, FX automation, Score automation, mixer controls and tempo. Late results from a cancelled/older project revision are discarded. Preview, stage audition and export read from the same completed routing result. Export does not silently write a dry master while an FX render is pending; the user is prompted to export after the background render finishes. If Pyo is unavailable or an effect fails, the UI reports the failure and keeps dry audio intact rather than modifying or partially overwriting the source.

## Validation

M22 adds coverage for:

- Role classification and automatic default routing, with kick/sub protected and unknown roles left dry.
- Schema-v1 migration to v2, preserving authored manual send and wet values.
- All four send tap semantics and pre/post fader gain handling.
- Wet-only returns, no dry double-addition, tail propagation and master extension.
- Source-buffer immutability, mute/solo/fader gates, mono/stereo and silence meters.
- Peak-safe matched-level audition copies; the production buffer remains identical.
- Cancellation and cache ownership at the worker API boundary.
- Offscreen UI auto/dry routing, per-bus send taps, stage audition selection and meter display.
- Existing M12/M13 automation compatibility and the standard Python/Windows regression suite.

The optional Pyo backend is still lazy-loaded. CI exercises the deterministic signal contracts with stand-in processors; it does not prove the sound of Pyo presets. A successful CI run is not a substitute for listening.

## Listening protocol and outstanding experimental sign-off

On the target Windows/Pyo setup, compare direct, insert, each send, SPACE, ECHO and master at matched levels. Listen to full mix and role pairs, including kick/snare, melody/hats and melody/ambience. Check dry/wet, low-volume and mono playback; assess attack preservation, low-end clarity, space depth and whether returns connect roles without washing out foreground. Run a long-tail case and watch the return-tail/headroom meters. These subjective and target-machine checks remain experimentally unverified.

## Explicitly out of scope

Arbitrary user graphs, feedback cycles, live plug-in hosting, parallel insert graphs, sidechain detector routing and a full channel-strip DAW remain future research. M22 keeps the fixed, inspectable insert + SPACE/ECHO model.


## M22 implementation close-out

The public routing renderer now defaults to role-aware inserts and sends when its routing argument is omitted. This closes the gap where the GUI and CLI could use automatic routing while callers of the core render API silently rendered everything dry. Explicit manual/dry routing remains supported as an intentional A/B action.

Schema v3 adds an inspectable role field to each stem route. v1 and v2 authored routing documents migrate to v3 without replacing their manual values. The master sum preserves mono or stereo channel count and applies master gain before the declared peak guard. The routing UI now describes automatic effects as part of the per-role source path rather than as a post-master effect, and makes clear that per-stem effect tagging is unnecessary.

The existing cancellable routing worker/cache, stage-audition path, matched-level copies and source-buffer ownership are retained. CI still cannot establish the subjective sound of optional Pyo processors, nor prove target-Windows responsiveness under the user's actual project size; those remain explicit listening/performance sign-offs.

**M22 is implemented and closed.**
