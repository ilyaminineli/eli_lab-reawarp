# M22 — Mixer and routing quality

**Status:** Planned  
**Depends on:** M12/M13 routing and automation; benefits from M18 and M21.

## Goal

Make the existing fixed SPACE/ECHO routing model transparent, predictable and safe. Expand observability and semantics before considering a general routing graph.

## Philosophy

The guides encourage role-aware space, clear source identity, restraint and controlled interaction. A shared return should connect musical roles without erasing their attacks or washing out the foreground.

## Scope

- Document and implement pre/post insert and pre/post fader send semantics.
- Add direct, insert, send contribution, return and master audition.
- Meter peak, RMS, crest and headroom at routing boundaries.
- Specify dry/wet law, bypass, latency alignment, tail propagation and master extension.
- Ensure preview and export use exactly the same signal semantics.
- Move long FX renders to workers with cancellation and safe result/cache ownership.
- Add matched-level snapshots for routing and automation.
- Preserve immutable dry stems and version portable routing/automation schemas.

## Explicitly out of scope

Arbitrary user graphs, feedback cycles between buses, live plug-in hosting and a full channel-strip DAW.

## Acceptance criteria

- Routing never mutates source stems.
- Preview/export are numerically consistent within a declared tolerance.
- Return tails are complete and align according to stage policy.
- Every route has documented gain staging and latency/tail reporting.
- Mute/solo/gain/pan/bypass behave identically in preview and export.
- Mono/stereo, silence, long tails, error/cancel and schema migrations are tested.
- UI remains responsive during long processing.

## Listening protocol

Level-match direct, insert, send, return and master. Audition full mix and role pairs. Compare dry/wet and low-volume/mono playback. Evaluate spatial depth, transient preservation, low-end clarity and whether the returns create relationships rather than a blanket wash.

## Deliverables

- Routing semantics specification.
- Meter/diagnostic layer and return audition.
- Asynchronous render/cache service.
- Versioned routing migration tests.
