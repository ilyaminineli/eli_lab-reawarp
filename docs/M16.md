# M16 — Score-driven render core

**Status:** The score-native renderer, shared musical clock, typed automation control bus, and score provenance are implemented. Migration of every legacy Generator planner and production synthesizer to emit and consume score events directly remains open.

## Goal

Make the universal score the canonical symbolic event representation consumed by an offline render core. Rational beat values remain exact until a score event is resolved onto a sample frame.

## Delivered in this increment

### 1. Shared render timeline

RenderTimeline centralises:

- rational beat to seconds conversion through TempoMap;
- beat to sample-frame conversion with deterministic nearest-frame rounding (ties round upward);
- frame to seconds and frame to rational-beat conversion;
- meter lookup and bar/beat queries through MeterMap;
- event start/end frame calculation, including tempo changes inside a note.

The tempo map integrates 60 divided by BPM over beat position. A linear BPM ramp is not approximated as a linear elapsed-time ramp. A meter change begins a new bar according to the existing MeterMap rules; pattern cycle lengths remain independent.

### 2. Score-native offline rendering

ScoreRenderer.render(score, sample_rate, ...) schedules Score.events and renders each voice into a separate dry stereo stem. Event onset and end frames are derived only from the score and its tempo map. Notes, hits, grains, and triggers are renderable; control and marker events remain symbolic.

The renderer provides a deterministic reference voice for basic note and transient audition. Applications can inject per-voice callbacks for production subtractive/FM/sample renderers. A callback receives the scheduled score event, render sample rate, and shared AutomationControlBus; it returns a mono or stereo float buffer with exactly the scheduled event length. Velocity, mono equal-power panning, frame placement, and finite-buffer validation are handled by the score renderer.

The reference voice is deliberately modest; it does not replace the M8–M15 instrument palette with one generic oscillator. It establishes the renderer contract so specialist production voices can be adapted one lane at a time.

### 3. Typed automation and one control clock

AutomationTargetRegistry defines target domain, units, value type, bounds, and supported interpolation modes. The default registry covers synthesis cutoff, resonance, gain and pitch; FX insert wet, SPACE/ECHO sends and shared return wet; and MIDI CC destinations, validated from channel/controller IDs.

AutomationControlBus evaluates beat-, second-, and frame-based lanes at absolute render frames. Frame-based lanes retain their source sample-rate reference when rendering at a different sample rate. Synthesis callbacks and downstream FX processors can request values or fixed-rate control samples from the same bus, avoiding independent beat/seconds conversions.

Custom targets remain supported through an explicit custom-target allowance. Strict registry validation rejects unknown targets, unit mismatches, out-of-range values, unsupported interpolation, and invalid MIDI CC addresses.

### 4. Project and provenance

ReawarpProject.export() continues writing the full project, aligned dry WAV stems, event records, and canonical score.json. Project metadata records the renderer version and a render-provenance record. Project-derived scores record score-renderer version, source generator version, root seed, sample rate, frame count, duration, named seed streams, and generator-family provenance.

Existing project schema and score schema version 1 remain readable. Old exports without M16 provenance fields continue to load; no stem is silently reconstructed from a score.

### 5. MIDI 1.0 representational limits

MIDI remains an interchange adapter, not the canonical render format:

- MIDI 1.0 note numbers are integer semitones; fractional pitch and exact frequency survive only in Reawarp text metadata.
- MIDI time is a finite ticks-per-beat grid. Reawarp rounds rational event positions to the nearest MIDI tick at the selected PPQ.
- MIDI tempo events are discrete microsecond-per-quarter-note values. Linear BPM ramps are sampled into tempo events at the requested export resolution; import therefore reconstructs a step map, not the original continuous ramp.
- MIDI time signatures are discrete conductor events. Reawarp rational score time and meter rules are richer than the MIDI conductor grid.
- Generic synthesis/FX automation is not natively portable in MIDI 1.0. MIDI CC lanes map to CC messages; additional Reawarp automation and event metadata rely on text meta events that other applications may strip.

## API

    from reawarp import ReawarpEngine, Score
    score = Score.load("output/my-composition/score.json")
    rendered = ReawarpEngine().render_score(score, sample_rate=48_000)

    rendered.stems       # dry stereo buffers keyed by voice_id
    rendered.render_master()
    rendered.schedule    # event IDs, sample frames, bars, and beat offsets
    rendered.controls    # shared frame-addressed automation bus for synth and FX

A production voice can be injected per voice:

    def lead_voice(scheduled, sample_rate, controls):
        cutoff = controls.sample(
            "synth.cutoff", scheduled.start_frame, scheduled.end_frame,
            step_frames=max(1, sample_rate // 1000),
        )
        return my_synth(scheduled.event, sample_rate, cutoff.values)

    result = ReawarpEngine().render_score(
        score, sample_rate=48_000, voice_renderers={"lead": lead_voice}
    )

## Compatibility boundary and remaining work

The existing Generator remains available and deterministic. Its specialised M8–M15 planners still use established MelodyEvent and PercussionEvent records with seconds-based positions while constructing the rendered project. ReawarpProject.to_score() converts those records into rational-beat MusicalEvent objects after generation. The new ScoreRenderer is a genuinely score-driven entry point, but the legacy Generator's complete planner-to-score migration is not claimed in this increment.

The next M16 integration pass should:

1. make percussion, motif, and melody planners emit MusicalEvent records directly, retaining source/generator metadata in event parameters;
2. adapt the existing role-specific synthesis and imported-sample renderers to consume ScheduledScoreEvent rather than their private seconds-based event classes;
3. make form and phrase boundaries use meter-map bar queries instead of constant-4/4 conversions;
4. route the existing M13 FX automation lanes into the typed score control bus.

Automated tests validate deterministic scheduling, step and ramp tempo conversion, meter changes, automation timebases and target validation, score render output, and project provenance. They do not establish subjective musical quality or target-machine Pyo performance; M14/M15 listening and profiling sign-offs remain separate.
