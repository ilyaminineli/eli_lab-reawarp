# M25 — Performance, portability and project durability

**Status:** Planned  
**Depends on:** M14 baseline and the contracts established by M18–M24.

## Goal

Make long-form work reliable, measurable, portable and archivable as the musical and DSP surface grows.

## Scope

1. **Target-machine sign-off**
   - Complete 30-second and 180-second, 48 kHz Windows benchmarks.
   - Record processor, memory, OS, Python, NumPy/SciPy, sample rate, config, wall time, real-time factor, peak RSS and allocation peak.
   - Run Pyo-enabled integration and critical listening at low volume and in mono.
   - Re-benchmark after major automation, DSP or mixer changes.

2. **Measured optimisation**
   - Profile planning, event count, voice rendering, sample processing, field layers, mixing, FX and export separately.
   - Optimise measured hotspots only; preserve deterministic reference implementations.
   - Add bounded buffers/caches and explicit memory budgets.
   - Do not port to GPU or rewrite native before measurements justify it.

3. **Project manifest and asset portability**
   - Define a manifest for app/algorithm/schema versions, config, Score, stems, source references/hashes, external assets, FX routing/automation, candidate ancestry and render environment.
   - Support portable relative asset references or explicit missing-asset diagnostics.
   - Never silently replace a missing source sample with another library item.
   - Include a reproducibility report distinguishing exact, same-environment and best-effort reproduction.

4. **Schema evolution**
   - Define compatibility windows and migrations for project, Score, routing, automation, sound-object and candidate data.
   - Add fixed archived fixtures from older versions and verify loading or actionable upgrade errors.
   - Avoid mutating source projects during migration.

5. **Application boundaries**
   - Reassess extraction of project session, generation jobs, FX render/cache, export and transport services from the main window.
   - Keep widgets responsible for presentation and input.
   - Define cancellation, shutdown, error recovery and resource cleanup.

## Acceptance criteria

- Full 180-second render/export/reopen works under declared memory/time budgets on the target machine.
- Published benchmark record contains machine and environment details needed to reproduce it.
- Older project fixtures load or report explicit migration requirements.
- Missing external assets are identified by stable ID/hash/path and never silently substituted.
- Render provenance describes seeds, versions, dependencies, tuning, source assets and routing.
- Long FX/generation jobs remain cancellable and do not block the interface.

## Not in scope

Speculative GPU acceleration, cross-platform bit-identical promises without evidence, or a general-purpose plug-in manager.
