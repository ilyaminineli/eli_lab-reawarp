# M15 — Integrated composition-to-production workflow

**Status:** integrated implementation in progress; validation tracked by CI.

M15 addresses the gap between Reawarp's existing mathematical generators, sample library, synthesis voices and production workspaces. The goal is not to expose more isolated controls; it is to make one compositional score drive the connected source, synthesis, stem and production stages.

## 1. One shared drum arrangement

The formal composition plan feeds a section-aware drum-part plan for kick, snare and hats. Each section has a role-family assignment, a role relationship, and a set of step positions. The arrangement evolves according to its formal function:

- introductions and establishment preserve space and establish anchors;
- development changes one or more role grammars without discarding the metric reference;
- uplifts and arrivals add activity and transition gestures;
- drops and voids subtract the main anchors rather than merely changing a density slider;
- returns recall the establishment kick family and step pattern.

A deterministic phrase-cycle phase walk and restrained boundary fills provide movement inside a section. `drum_change_intensity` and `drum_part_cycle_bars` bound the amount and rate of change. Turning off `pattern_follow_structure` restores the prior sparse, manually controlled drum generator.

## 2. Sample and synthesis are two sources for one instrument

The role event score is built once. For every event, Reawarp chooses a synthesis contribution and a sample contribution, then places both into the same role stem.

Source modes:

| Mode | Behaviour |
|---|---|
| `automatic` | Section-aware contribution changes based on phrase function |
| `synth` | Use the synthesis voice only |
| `sample` | Use the selected sample only |
| `hybrid` | Use a fixed sample/synthesis balance |

Hybrid architectures:

- `transient_body`: use a short, faded sample segment as the transient and let the synthesizer provide the body/tail;
- `layered`: use a controlled parallel mix of the full sample and full synthesis voice.

The source mix and selected sample provenance are attached to event records and project metadata. Separate `sample_kick`, `sample_snare` and `sample_hat` stems are no longer created, because those lanes are now a single hybrid instrument. Break samples remain a separate transformed phrase layer.

## 3. Existing library and analysis dependencies

The Generator discovers the repository's bundled files under `samples/`, classifies the available kick, snare/clap and hat/cymbal sources, and provides a per-role custom override. The Library can browse and audition the same bundled files without indexing them first, then send a selected sample directly into the corresponding Generator role.

The audio reader uses SciPy's polyphase resampler when installed and falls back to NumPy interpolation. The searchable library's feature extraction adds optional librosa HPSS (harmonic/percussive separation) and onset-density analysis while retaining the NumPy-only baseline. The pitch-field adapter provides scale collections in the core renderer and an optional music21 Scale bridge for richer notation/theory workflows.

Pyo and other optional synthesis dependencies are not made hard requirements by this increment. The deterministic NumPy path remains the reference renderer.

## 4. Integrated Generator workflow

- The Generate Composition action remains pinned outside the scroll area.
- The Generator presents bundled samples, source mode, hybrid architecture, sample contribution and transient window together.
- The render summary displays the phrase sequence, section-to-drum-family map, section-specific synthesis profiles, source mode and sample provenance.
- After generation, shortcuts connect directly to Stem Mixer, FX Lab and Library.
- The Library's bundled-sample browser can route playable material back into kick, snare, hat or break roles in the Generator.

The purpose is to make the pathway explicit: **compose → arrange parts → choose/automate sources → render aligned stems → mix/route/automate/export**.

## 5. Musical design constraints

This increment follows the IDM guide principles: preserve identity-bearing anchors, build inter-relationships among independent parts, change one principal dimension at a time, use negative space as a structural event, and make returns recognisable without turning them into unaltered repetition.

Automation is deterministic and seed-addressable. A fixed profile choice remains fixed; automatic profile choices are resolved at section boundaries, and return sections recall the establishment profile. User-selected sample files remain unchanged.

## 6. Regression coverage

New tests cover:

- bundled sample discovery and custom-file overrides;
- deterministic, linked kick/snare/hat part evolution;
- return-anchor recall and the static fallback mode;
- shared event scores across sample/synthesis sources;
- sample-only, hybrid-transient and layered hybrid output;
- pitch-field quantisation of geometric melody events.

CI also checks the desktop Generator, the pinned action, bundled sample controls, and the connected production shortcuts.
