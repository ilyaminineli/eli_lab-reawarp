# M6 — Searchable Sample and Stem Library

Status: implemented as a local Python API and command-line tool.

M6 gives Reawarp a persistent memory of the material it creates and the source audio it uses. The library is an offline subsystem; it does not own the render engine, alter source audio, or require a plug-in host.

## 1. Goals

- Index imported samples, exported stems, master renders, and referenced source files.
- Preserve file hashes, paths, project metadata, role tags, and project-family provenance.
- Describe assets using low-cost timbral, dynamic, and rhythmic features.
- Search by file/metadata text, role, type, and tags.
- Rank assets by similarity to an existing indexed audio asset.
- Organize choices into named collections.
- Reconstruct project variation families and their parent-child relationships.

The SQLite catalog is local to the machine. The audio files remain where they are; indexing does not copy, move, rewrite, or normalize them.

## 2. Architecture

```text
WAV / optional SoundFile formats
              |
              v
       Audio file reader
              |
              v
  NumPy descriptor extraction
  ├── duration / peak / RMS / crest
  ├── zero-crossing rate
  ├── spectral centroid / rolloff / flatness
  └── transient density / tempo hint / 16-bin rhythm histogram
              |
              v
        SQLite catalog
  ├── assets and tags
  ├── collections
  └── projects and variation genealogy
              |
              v
      Python API / CLI
  ├── text and metadata search
  ├── nearest-feature similarity
  ├── collection management
  └── project-family inspection
```

The core implementation uses Python's `sqlite3`, filesystem APIs, and NumPy. WAV decoding is supported by Reawarp's built-in PCM reader. FLAC, AIFF, and OGG are available when the optional `soundfile` dependency is installed.

## 3. Audio descriptors

Every indexed file is analysed at 22.05 kHz mono. The original sample rate, channel count, size, modification time, and SHA-256 digest are retained separately.

| Descriptor group | Values | Use |
|---|---|---|
| Duration | seconds, analysis frame count | One-shots, loops, long textures |
| Dynamics | peak, RMS, dBFS, crest factor | Loudness and transient character |
| Spectrum | centroid, 85% rolloff, flatness | Brightness, bandwidth, noise-like vs tonal |
| Time-domain | zero-crossing rate | Noisy/roughness proxy |
| Rhythm | onset count/density, interval CV, tempo hint | Sparse, steady, dense, irregular |
| Pattern | normalized 16-bin onset-phase histogram | Coarse rhythmic similarity |

Transient extraction reuses Reawarp's dependency-free positive energy-flux detector. Descriptors are deterministic for the same audio file and analysis version.

## 4. Similarity search

The nearest-neighbour query compares normalized combinations of:

- log duration ratio;
- spectral centroid, rolloff, and flatness;
- RMS and crest-related dynamics;
- zero-crossing rate;
- onset density and interval regularity;
- tempo hint and the 16-bin rhythm histogram.

The current ranking is a transparent weighted distance converted to a 0–1 similarity score. It is a useful retrieval heuristic, not a learned embedding or a claim of perceptual identity. A reference query ranks the exact source first with similarity 1.0.

Search can also constrain asset type, role, text query, or required tags.

## 5. Asset types and project indexing

`index_file()` indexes one audio asset. Supported asset types are:

- `sample` — standalone source material;
- `stem` — an exported project stem;
- `master` — a project master render.

`index_project()` reads `project.json`, indexes all listed stem WAVs and `master.wav`, and indexes referenced source samples when their paths still exist locally. The project ID is path/content-specific. The family ID is derived from the canonical generation configuration, so base and regenerated versions share a family.

A variation record stores the changed stem, variation number, seed/configuration family, and parent project ID. The parent is linked even when the variant is indexed before its root project; indexing the root later reconciles the family.

## 6. Collections

Collections are named, persistent sets of asset IDs stored in SQLite. Assets may belong to multiple collections. Collection membership does not duplicate audio or asset records.

The Python API supports create/update, add, remove, list, and retrieve operations. The CLI exposes those operations under `reawarp-library collections`.

## 7. Python API

```python
from reawarp.library import SampleLibrary

with SampleLibrary() as library:
    report = library.index_directory("samples")
    results = library.search(role="kick", tags=("idm",), limit=20)

    collection_id = library.create_collection(
        "Chosen kicks", "Auditioned low-frequency voices"
    )
    library.add_to_collection(
        "Chosen kicks", [asset.asset_id for asset in results[:3]]
    )

    project = library.index_project("output/my_project")
    variants = library.genealogy(project["family_id"])
```

## 8. CLI

```powershell
reawarp-library index samples/
reawarp-library index output/my_project/
reawarp-library search --role kick
reawarp-library search --similar-to ASSET_ID --limit 12
reawarp-library collections create "Metallic Breaks"
reawarp-library collections add "Metallic Breaks" ASSET_ID_1 ASSET_ID_2
reawarp-library collections show "Metallic Breaks"
reawarp-library genealogy FAMILY_ID
```

The default catalog is `~/.reawarp/library.sqlite3`. Override it with `--db path/to/library.sqlite3` before the subcommand.

## 9. Determinism, privacy, and integrity

- All feature analysis runs locally; there is no upload or remote service.
- Source files are read-only from Reawarp's perspective.
- SHA-256 and resolved paths make file identity and updates auditable.
- Re-indexing an unchanged path and hash reuses saved descriptors.
- SQLite stores only metadata, feature vectors, collections, and project relationships; audio remains in its original location.
- Similarity ranking uses explicit descriptors and weights rather than opaque model embeddings.

## 10. Boundaries and next work

M6 provides the persistent data layer, feature extraction, API, and CLI. It does not yet add a dedicated visual library browser, waveform audition inside search results, embedding models, cloud synchronization, or automatic tagging from machine learning. Those can be added as an M6.1 interface layer without changing the database or renderer contracts.
