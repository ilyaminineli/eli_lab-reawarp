# M24.1 — Convolution and designed impulse-response instruments

**Status:** Portable reference implementation in place; technical CI gate pending. Human matched-level listening remains an independent acceptance sign-off.  
**Track:** [M24 — Advanced DSP research modules](M24.md)  
**Depends on:** M21 sound-object identity/provenance and M22 source ownership, tail, latency and matched-audition semantics.

## Musical purpose

Convolution should be treated as an instrument excited by a source, not only as a room simulator. A short transient can excite a designed inharmonic body; a drum fragment can acquire the spectral/time signature of a glass, plate, pipe, machine or fictional resonator. A deliberately designed response can also imprint resonant colour on a sustained source.

Representative arrangement use-case: a sparse metallic percussion role uses a dry click as the transient and an inharmonic resonant response as its body/tail. Keep the dry event available so the rhythmic attack remains articulate; the response supplies the longer spectral identity and negative-space fill. A modest parallel blend is an authored sound-object choice, not an implicit extra mixer graph.

This follows the sound-design guide's treatment of convolution beyond room simulation and of transient/body/tail identity. See sections 20.4, 21.1, 23, 27 and 54.

## Scope and boundaries

Included:

- Deterministic modal impulse-response design with optional low-level decaying noise and small stereo divergence.
- Imported or designed mono/stereo IR audio represented by an immutable, hash-addressed model.
- Offline causal FIR convolution using uniform partitioned overlap-add.
- Explicit dry/wet blend, full response tail, sample-rate validation, exact bypass and signal diagnostics.
- A portable compressed NPZ archive containing a JSON manifest and float32 samples.
- Benchmark and matched-level listening-example scripts.

Explicitly excluded:

- Real-time/streaming convolution, live IR capture, true-stereo 2x2 matrix convolution, automatic IR resampling, partition crossfades, GPU acceleration, automatic gain/normalisation, master insertion and default role routing.
- STFT envelope transfer, vocoder, spectral delay, freeze, time stretch or generic cross-synthesis. The spectral-imprint helper in this module is a causal FIR coloration using the same convolution contract; it is not a separate spectral-analysis algorithm.

The module is available under \`reawarp.dsp.convolution\`; it is not exposed as a default M22 FX preset or return.

## Algorithm and units

### Partitioned overlap-add reference

For input \(x[n]\) and finite response \(h[n]\), the wet output is causal linear convolution:

\[
y[n] = \sum_{k=0}^{M-1} h[k]x[n-k]
\]

The response is split into uniform partitions of \(B\) frames. Each partition and input block is zero-padded to \(2B\), transformed with an RFFT, multiplied, summed into the corresponding output block, inverse transformed and overlap-added. The reference implementation keeps a bounded ring of input spectra, so it does not retain the entire input spectrogram.

- Block size: power of two, 64–8192 frames; default 1024.
- FFT size: \(2B\).
- Partition count: \(\lceil M/B \rceil\).
- Output frames for a non-empty full wet render: \(N+M-1\).
- Full wet tail: \(M-1\) frames, or \((M-1)/f_s\) seconds.
- Offline algorithmic latency/alignment offset: zero frames. This does not imply a real-time streaming latency guarantee.

### Designed modal impulse response

Each response mode has frequency in Hz, linear gain, decay time in seconds and optional initial phase in radians. A modal response is formed as:

\[
h[n] = \sum_i g_i \sin(2\pi f_i n/f_s + \phi_i)e^{-n/(f_s\tau_i)}
\]

Optional diffuse noise is generated from a local NumPy generator using the saved seed and then exponentially decayed. A small stereo spread applies a symmetric frequency divergence to the left and right modal responses. This remains dual-mono processing at convolution time; there is no hidden cross-channel matrix.

No peak or energy normalisation is performed. Mode gains are authored values, and the diagnostics disclose peak, RMS, headroom and over-unity status.

## API and portable schema

Public API:

- \`ImpulseResponse\`: immutable samples, sample rate, name/ID, source and processing identities, seed, design metadata and audio SHA-256.
- \`design_resonant_ir(...)\`: create a deterministic modal response.
- \`convolve_partitioned(audio, impulse_response, sample_rate, wet=1.0, block_size=1024, bypass=False)\`: render and return \`ConvolutionResult(audio, diagnostics)\`.
- \`spectral_imprint(...)\`: explicitly named wrapper over the same causal FIR coloration semantics.
- \`ImpulseResponse.save(path)\` / \`ImpulseResponse.load(path)\`: save/recover the portable IR.

Archive schema is \`reawarp_impulse_response\`, version 1. The NPZ contains exactly a JSON \`manifest\` and a float32 \`samples\` array. The manifest records sample rate, frame count, channel count, duration, seed, design, source/processing identities, sample encoding and SHA-256 of canonical little-endian float32 samples. Load verifies format, schema, dimensions and hash. External IR recordings remain user-owned assets; provenance and licence information can be retained in the design metadata.

The archive does not embed an executable DSP graph or external code. It can be inspected and validated with NumPy only.

## Parameter ranges and validation

| Parameter | Range / unit | Behaviour |
|---|---|---|
| Sample rate | positive integer Hz; designer requires at least 1000 Hz | Must match the input exactly; mismatch raises rather than silently resampling |
| IR duration | 1 sample to 60 seconds | Determines response frame count and maximum tail |
| Mode count | 1–256 | Every mode is validated independently |
| Mode frequency | 0.1 Hz to 0.499 × sample rate | Prevents Nyquist-edge/invalid frequency values |
| Mode gain | 0–4 linear | No automatic normalisation |
| Decay | 0.001–120 seconds | Exponential amplitude decay |
| Diffuse noise | 0–1 normalized | Zero by default; seeded local generator |
| Stereo spread | 0–0.05 normalized | Zero returns mono; positive value designs two slightly divergent channels |
| Wet | 0–1 linear | Linear dry/wet crossfade; wet-only tail retained |
| Block size | power of two, 64–8192 frames | Partitioned offline processing |

IR and source arrays must be finite mono or stereo real audio. The response is immutable after construction. Channel policy is explicit: mono IR filters each source channel independently; stereo IR with mono source produces stereo by applying the left/right response to the duplicated source; stereo input plus stereo IR is dual-mono left-to-left/right-to-right. No L/R crossfeed is performed.

Sample-rate conversion is caller-owned and explicit. The existing M21 non-destructive resampling contract can be used to create a new IR with its own provenance; M24.1 never resamples silently.

## Sample-rate, processing and latency policy

The engine is offline, frame-addressed and partitioned. There is no audio-device callback or fixed render deadline. The zero-latency figure refers to causal file alignment only. There is no look-ahead, pre-delay or compensation offset. A response's own early reflections and decay are part of the IR, not reported as algorithmic latency.

The output always retains the full finite IR tail. No auto-trim, gate or tail threshold is applied. For wet values below 1, the dry input is zero-padded to the full wet output length before the linear crossfade. At wet 0 or explicit bypass, the function returns a separate dry copy at exactly the source length and does not require an IR.

## Headroom, denormals and finite output

- Input arrays and IRs are copied/treated as read-only; source buffers are not edited.
- There is no hidden gain compensation, normalization, limiter or clipping.
- Peak, RMS, headroom and over-unity state are recorded.
- Non-finite output raises \`FloatingPointError\`; non-finite input/IR is rejected.
- Subnormal sample count is measured and reported. Values are not flushed to zero, avoiding an undocumented change to the tail.
- Mono, stereo, silence, impulse, and dual-channel IR cases are covered.
- Tail and output-buffer sizes are explicit; there is no recursive feedback loop, so feedback stability is not applicable.

## Deterministic random-stream policy

Convolution itself uses no random numbers. Modal IR generation has no random component unless diffuse noise is enabled; that noise uses a local \`numpy.random.default_rng(seed)\` and does not touch global RNG state. The seed and design parameters are included in the portable manifest. The target contract is deterministic same-environment output; FFT implementations may differ slightly across NumPy/platform builds, so cross-platform bit identity is not promised.

## Dependencies and licensing

The reference implementation uses the project's mandatory NumPy dependency only. No Pyo, SciPy, librosa, native convolution library or GPU runtime is required. No external IR sample is bundled. A user-provided or third-party IR must retain its author, source, licence and permitted-use information in accompanying provenance metadata; an audio hash verifies identity, not rights.

## CPU/memory benchmark

Run:

\`\`\`bash
python scripts/benchmark_m24_convolution.py --durations 0.5 5 --ir-durations 0.25 1.5 --sample-rates 22050 48000 --output benchmark-m24-1.json
\`\`\`

Each case records Python/NumPy/platform metadata, source and IR duration, partition count, block/FFT sizes, wall/processing time, real-time factor, output bytes, estimated working bytes, tracemalloc peak, peak and headroom. The module's working-byte estimate accounts for the main NumPy buffers; tracemalloc may not observe every native allocation. No target-machine performance claim is made until the user's representative Windows workloads are benchmarked.

## Matched-level listening example

Generate an example set:

\`\`\`bash
python scripts/render_m24_1_listening_example.py --output output/m24-1-glass-machine
\`\`\`

The script writes:

- \`01-excitation-matched.wav\`
- \`02-convolution-matched.wav\`
- \`03-role-blend-matched.wav\`
- \`glass-machine-ir.npz\`
- \`render.json\` with IR hash, timing/tail/headroom diagnostics and -18 dBFS RMS/0.95-peak-ceiling match reports.

The example uses a sequence of short percussion-like excitations and an inharmonic glass-machine response; its 28% role blend is included to test whether the dry attack remains perceptible while the response fills the gaps. These are matched audition copies, not production audio. Human evaluation must listen in full context, in mono and at low monitoring level, and record whether the effect contributes a distinct identity without masking the next event. No artistic acceptance is inferred from script generation or CI.
