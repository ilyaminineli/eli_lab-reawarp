# M18 — Musical automation and control performance

**Status:** Implementation complete; cross-platform CI evidence recorded. Target-machine profiling and matched-level Pyo listening remain experimentally unverified cross-cutting sign-offs tracked under M14/M22.  
**Depends on:** M16/M17 Score and typed AutomationControlBus.

## Goal

Make Score automation a compositional instrument: musical movement is writable and inspectable as deterministic control trajectories, not hidden in renderer callbacks or limited to post-FX wet curves.

## Implemented contract

### 1. Typed target catalogue and validation
- Targets declare domain, unit, value type, legal range, interpolation modes, smoothing, hysteresis and update clock.
- The registry covers synthesis, composition, sample contribution, spatial controls, fixed FX controls and MIDI CC destinations.
- Validation rejects unit mismatches, unsupported interpolation, out-of-range values and invalid value types. M13 stem-aware IDs retain their established compatibility contract.

### 2. Scoped lanes and deterministic sources
- Lanes support global, section, role and event scopes. Precedence is global → section → role → event; absolute lanes replace and relative lanes offset inherited values.
- Reusable LFO, envelope, stepped, random-walk and phrase-curve sources retain rational beat positions and deterministic seeds.
- LFOs support sine, triangle, square and saw. Source curves are materialised once per control bus.
- Modulations support amount, polarity, add/multiply modes, output bounds, explicit base values, scope, smoothing, hysteresis and free/event/role/section retrigger.

### 3. Canonical Score and render integration
- Score JSON round-trips scopes, sources and modulation relationships without changing the schema version; older M17 Score JSON remains readable.
- ScoreRenderer resolves event/role/section context on RenderTimeline, including tempo ramps.
- Event/role consumers include stable event probability, velocity scale, role activity, deterministic density thinning, bounded syncopation placement, articulation and sample contribution.
- Production voices consume cutoff/resonance/gain, pitch-at-note-onset, per-note ADSR and continuous vibrato across subtractive, FM, additive, modal and granular palettes.
- Instrument-specific consumers include wavetable position, additive partial balance and granular size/position/density only where the selected voice family supports them.
- Spatial pan and stereo width are applied by ScoreRenderer. Scoped/inactive controls preserve the original voice parameter for unrelated roles.
- Probability gates are stable for a symbolic event and its generated sample/break trigger. Controls do not delete or mutate the canonical symbolic Score.

### 4. Fixed FX routing integration
- The shared Score control bus drives the existing fixed router's per-stem insert wet, per-stem SPACE/ECHO sends, and SPACE/ECHO return wet.
- Stem-aware IDs are explicit: `stem.<name>.insert_wet`, `stem.<name>.send.space`, `stem.<name>.send.echo`, `bus.space.wet`, and `bus.echo.wet`.
- The M13 schema-v1 JSON adapter remains readable and compatible. Legacy JSON and a Score control bus cannot be supplied simultaneously.
- The generic catalogue entries `fx.insert.wet` and `fx.send.*` describe classes of destinations; the live fixed router uses explicit stem/bus IDs to prevent ambiguous fan-out. The UI offers those concrete destinations when a Score is loaded.

### 5. Authoring workflow
- Stem Mixer provides separate FX AUTOMATION and SCORE CONTROL tabs.
- Score Control provides scope-aware target/source authoring, five source shapes, LFO waveform selection, retrigger/phase and seed controls, template presets, curve preview/editing, add/remove, undo/clear and Apply & Re-render.
- Role, section and event scopes suggest IDs from the active Score while preserving editable custom ID entry.
- Applying controls re-renders event-backed Score voices while preserving specialist whole-field texture and ambience stems.

## Planner semantics and boundary

Role density, syncopation and articulation are consumed as deterministic Score render-performance transformations at event/phrase boundaries. They do not rewrite the canonical symbolic Score or rerun the upstream stochastic planner. This keeps rendering idempotent and preserves Score provenance. A future interactive planner-regeneration interface would require explicit regeneration provenance and is not implied by these controls.

## Automated acceptance

The existing focused M18 test suite covers typed/scoped serialization and old-record compatibility; deterministic source generation and modulation; tempo-ramp timing; scope isolation and active masks; smoothing/hysteresis; probability boundaries; event density, syncopation and articulation; ADSR/vibrato across five melodic palettes; wavetable/partial/granular destinations; and downstream FX control-bus compatibility.

**Recorded CI evidence:** 129 tests passed per job on Linux Python 3.10–3.12 and Windows Python 3.11. This close-out records the repository's existing evidence; it does not claim a new CI execution or local audio audition in this session.

## Experimental sign-offs retained outside implementation status

1. Run 30 s and 180 s, 48 kHz benchmarks on the target Windows/RTX 4060 machine, recording hardware, Python/NumPy/SciPy versions, render time, real-time factor and peak memory.
2. Render matched-seed comparison variants: no automation, slow macro, event-relative envelope, coupled modulation and stem-aware insert/send/return automation.
3. Audition full mix and isolated roles at matched perceived loudness. Record transient integrity, brightness, pitch stability, stereo width/mono compatibility, foreground masking and negative space.
4. Verify optional Pyo FX integration on the target setup.

These items remain **experimentally unverified** rather than being inferred from unit tests.

## Explicitly out of scope

Real-time MIDI/OSC control, a general-purpose modular modulation graph, arbitrary audio-rate patch cables, live audio followers, and replacement of deterministic offline rendering.

## Decision

M18 is closed as an implementation milestone. The deterministic control model, production voice consumers, spatial processing, fixed-router consumers and authoring workflow are integrated. Hardware profiling and critical listening remain cross-cutting M14/M22 sign-offs.
