# M18 — Musical automation and control performance

**Status:** Planned  
**Depends on:** M16/M17 Score and typed AutomationControlBus  
**Cross-cutting gate:** M14 target-machine profiling remains separate.

## Goal

Make score automation a compositional instrument. Musical movement should be writable and inspectable as control trajectories, not hidden inside renderer callbacks or represented only by post-FX wet curves.

## Philosophy

The IDM guides treat filter sweeps, pitch/register movement, decay, grain density, spatial movement, feedback and pattern probability as compositional material. Curves should create relationships between recurring events and larger phrase/section development. More automation is not automatically better: modulation depth and hierarchy must support the foreground and preserve recognisable sound identity.

## Scope

1. **Typed target catalogue**
   - Synthesis: gain, pitch/register, cutoff, resonance, attack/decay/release, modulation depth/rate, wavetable position, partial balance, grain size/position/density.
   - Event/composition: velocity scale, role activity, density, syncopation, event probability, articulation and sample contribution.
   - Spatial/FX: pan, width, sends, insert/return wet and selected delay parameters.
   - Every target declares domain, unit, value type, range, smoothing, update clock and legal interpolation.

2. **Automation layers**
   - Event-relative expression for note/hit envelope and articulation.
   - Role-level trajectories over beats.
   - Section/phrase macros and global arrangement controls.
   - Support absolute and relative values with documented precedence. Static config remains the default when no lane exists.

3. **Control generators**
   - Deterministic LFOs, envelopes, stepped sequences, bounded random walks and phrase/section-derived curves.
   - Optional follower/analysis curves imported as frozen control data; live analysis is not required.
   - Independent named seed streams for stochastic control sources.

4. **Modulation relationships**
   - Explicit source, destination, amount, polarity, range, smoothing and phase/retrigger policy.
   - Coupling examples: brightness with resonance; transient energy with decay; grain position with phrase function; width with tail; pitch instability with register.
   - Hysteresis and smoothing prevent audible chatter and abrupt coefficient jumps.

5. **Score and render integration**
   - All curves remain serializable Score automation lanes on the shared beat clock.
   - Tempo ramps and meter changes resolve through RenderTimeline.
   - The same control bus remains consumable by event renderers and compatible FX processors.
   - Define efficient control sampling rates for slow modulation versus per-frame automation; avoid unnecessary full-rate Python loops.

6. **User workflow**
   - Show active automation targets and ranges.
   - Inspect/edit curves, choose source generator and destination, preview one role, bypass and reset.
   - Provide compositional templates: slow reveal, phrase pulse, call-response hand-off, unstable surface over stable anchor, and transition collapse.

## Explicitly out of scope

Real-time MIDI/OSC control, a general-purpose modular modulation graph, arbitrary audio-rate patch cables, and replacement of deterministic offline rendering.

## Acceptance criteria

- All registered targets validate unit, range, clock, smoothing and interpolation.
- Beat-, bar-, phrase-, section- and event-relative control maps resolve to expected frames under fixed and ramped tempo.
- Score JSON round-trips every automation type and modulation relationship.
- Fixed seed/config yields repeatable control trajectories and audio buffers.
- A target change demonstrably affects only its intended destination.
- Smoothing/hysteresis prevents discontinuities in control values and finite audio.
- Existing M13 JSON remains readable and round-trips through the compatibility adapter.
- Tests cover boundary points, pre-first defaults, loop points, tempo ramps, modulation phase/retrigger, range clamps and independent seeds.

## Listening protocol

Render the same material with no automation, one slow macro, one event-relative envelope and one coupled-modulation relationship. Compare full mix and isolated roles at matched level. Listen for intelligible motion, loss of transient identity, excess brightness, unstable pitch and automation that competes with the foreground.

## Deliverables

- Target catalogue and schema documentation.
- Control-source/modulation model and deterministic generators.
- Score integration and compatibility tests.
- Minimal automation editor/preview.
- A small listening fixture pack documenting musically meaningful results.
