# M10 — Offline FX Lab

## Intent

M10 adds a focused sound-design workspace rather than another automatic composition layer. The four documents in `docs/guides/` remain the musical specification:

- Keep source identity audible. Effects should transform a role, not erase the reason the sound exists.
- Treat transient, body, and tail as separate perceptual components.
- Use contrast and negative space; do not increase effect count as a substitute for arrangement.
- Keep the low-frequency anchor stable, level-match comparisons, and preserve a dry reference.
- Prefer a small number of purposeful transformations and make their order explicit.

The FX Lab is deliberately separate from the NumPy generation engine. Existing Reawarp projects and samples remain unchanged unless the user exports a processed copy.

## Implemented

### Processing backend

- Optional Pyo offline renderer, loaded lazily only when an FX render is requested.
- Offline server mode; no audio output device is opened for the actual render.
- Mono and stereo file input, with source sample rate and channel count preserved.
- Float32 intermediate file I/O and 24-bit PCM WAV export.
- A final safety trim is applied only when the rendered peak exceeds 0.98; no routine loudness normalisation is performed.
- Configurable global wet/dry balance and explicit tail allowance up to 12 seconds.
- The dry source buffer is kept intact and available for A/B audition.

### Available effect stages

| Stage | Pyo processor | Parameters exposed by current presets |
|---|---|---|
| High-pass | `ButHP` | Cutoff |
| Low-pass | `ButLP` | Cutoff |
| Band-pass | `ButBP` | Centre frequency, Q |
| Saturation | `Disto` | Drive, post-filter slope |
| Delay | `Delay` | Delay time, feedback |
| Reverb | `Freeverb` | Room size, damping |
| Frequency shift | `FreqShift` | Shift in Hz |

Each stage has an explicit mix in its chain. A final global wet/dry blend controls the processed path against the original source.

### Starting chains

| Preset | Purpose |
|---|---|
| `restrained_space` | Low-frequency/high-frequency shaping and a short dark room |
| `tape_echo` | Filtered echo with restrained feedback |
| `metallic_machine` | Narrow band focus, a small frequency displacement, and a diffuse tail |
| `digital_fracture` | Moderate saturation, bandwidth reduction, and a short repeat |

These are starting points, not automatic mastering or genre presets. Their parameters are intentionally bounded.

## User workflow

1. Open **FX LAB**.
2. Load a mono or stereo WAV, FLAC, AIFF, or OGG source.
3. Choose a chain, set global wet/dry amount, and set a tail allowance.
4. Render. The dry source and processed result appear in separate waveform/spectrogram previews.
5. Audition either version and export the processed copy as a new WAV.

The same engine is available from the command line:

```powershell
reawarp-fx input.wav output_fx.wav --preset tape_echo --wet 0.70 --tail 2.0
reawarp-fx --list-presets
```

## Install and dependency policy

Install Pyo only when the FX Lab is needed:

```powershell
python -m pip install -e ".[pyo]"
```

Pyo and SoundFile are not core dependencies. The GUI can still open without Pyo; attempting to render then gives an actionable installation message. The standard mathematical generator, score model, sample library, and break transforms do not import Pyo.

Pippi remains a separate experimental research dependency. The current package line is pre-release, and the published `2.0.0b16` wheel is Linux/CPython 3.14; Windows receives a source distribution and may need a native build environment. It is therefore not in the default install group or the uncommented requirements inventory.

Pedalboard remains commented in the dependency inventory because its upstream distribution is GPL-3.0. The MIT project must not pull it in casually as an implementation shortcut.

## Validation and limitations

- CI compiles the package, smoke-renders the normal Reawarp CLI, imports the desktop entry point, checks the library CLI, and verifies the FX preset registry without requiring Pyo.
- The Pyo renderer is isolated behind a lazy optional import. A local environment with Pyo installed is required to exercise the actual DSP render.
- No automated test suite is recreated; the repository's deleted tests remain deleted.
- Actual sound quality still needs audition on the Windows setup and listening chain. CI cannot judge whether an echo, resonant treatment, or reverb tail is musically appropriate.

## Follow-on milestones

M11 adds the editable serial-chain workflow documented in [M11.md](M11.md): stage insertion/removal, ordering, parameter editing, and portable JSON save/load. The following capabilities remain deferred:

- Per-stem effect inserts inside the Generator mixer.
- Tempo-synchronised delay values derived from a project BPM.
- Convolution reverb, custom impulse responses, spectral delay, cross-synthesis, and oversampled nonlinear processing.
- Automation lanes, modulation routing, sidechain interaction, and VST hosting.

These should be separate additions, introduced only with clear controls, headroom management, and A/B validation.
