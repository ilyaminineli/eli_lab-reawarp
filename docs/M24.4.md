## Musical purpose

Nonlinear processing adds harmonics, changes transient shape and can turn a simple source into a dense or unstable sound. It can add controlled body to percussion, increase bass audibility or create inharmonic digital texture. Oversampling is a quality/CPU trade-off; intentional aliasing remains a valid separate aesthetic choice.

A representative use-case is bright metallic percussion: compare the native-rate version with 2x/4x/8x processing, retain the transient shape and choose the least expensive quality level that produces the intended spectrum. Compare at matched monitoring loudness.

## Transfer functions and API

`oversampled_waveshaper(audio, sample_rate, *, shape="tanh", drive=2.0, oversample=4, clip_level=1.0, output_gain=1.0, wet=1.0, taps_per_phase=16, bypass=False)` returns `NonlinearResult(audio, diagnostics)`.

Five explicit curves are available:

- `tanh`: (y=	anh(dx)), smooth saturating curvature.
- `atan`: (y=2arctan(dx)/pi), slower smooth saturation.
- `hard_clip`: (y=mathrm{clip}(dx,-c,c)), explicit threshold.
- `sine_fold`: (y=sin(dx)), periodic fold-like harmonics.
- `softsign`: (y=dx/(1+|dx|)), rational soft saturation.

Drive (d) is 0.01–32 linear; clip level (c) is 0.01–4; output gain is 0–4 linear; wet is 0–1. Curves are not loudness-normalized. Output gain is an authored post-shaper gain, not automatic compensation.

## Oversampling and reconstruction

Allowed factors are 1, 2, 4 and 8. Factor 1 is an unfiltered native-rate comparison. Factors above 1 use zero-insertion interpolation with a symmetric Kaiser-windowed sinc FIR, run the nonlinearity at (F_s 	imes L), then use the matching low-pass FIR before decimation. The filter's ideal cutoff is the destination Nyquist; its finite transition band and finite stopband attenuation mean aliasing is reduced, not guaranteed absent. The Kaiser beta is 8.6. `taps_per_phase` (8–64) controls FIR support and CPU cost.

Both FIR group delays are symmetric and trimmed by the offline renderer. The returned frame count is exactly the input count and reported file-alignment offset is zero. This is not a real-time plugin latency guarantee. The FIR output is not post-normalized and no limiter, DC removal or denormal flushing is applied.

## Signal contract and diagnostics

Sample rate is an integer of at least 1 kHz; input must be finite mono/stereo audio. Channels are processed independently without crossfeed. Exact bypass or `wet=0` returns an exact-length dry copy and does not run the filters. Source data is never mutated. Output is checked for finite values and diagnostics include transfer shape, drive, oversampling factor, internal rate, FIR support, delay compensation, working-memory estimate, processing time, output bytes and peak/RMS/headroom.

NumPy only; no SciPy resampler, Pyo, plugin host, GPU or mandatory native backend. Performance scales with factor, FIR support and audio length; use measured benchmark evidence before considering a real-time implementation.

## Benchmark and listening

```bash
python scripts/benchmark_m24_4_nonlinear.py --duration 5 --sample-rate 48000 --output m24-4-benchmark.json
python scripts/render_m24_4_listening_example.py --output output/m24-4-oversampled-nonlinear
```

The benchmark compares 1x/2x/4x/8x with identical source/curve/drive and records environment, wall time, RTF, traced memory, engine buffer estimate and diagnostics. The listening set writes the dry source and each factor render plus a JSON report. It does not normalize outputs; use external matched monitoring level for the comparison.
