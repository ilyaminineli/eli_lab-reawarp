# M3 — Break Transformation & Advanced Synthesis

Status: implemented in the NumPy core.

M3 extends Reawarp from procedural loop generation into a deterministic break-sample transformation engine. All operations work on in-memory float32 NumPy arrays. Imported files are never overwritten. The transformations are available through the Python API and, when a break sample is supplied, through the CLI.

## 1. Analysis and slicing

### Transient detection

`detect_transients(audio, sample_rate, threshold=0.22, min_interval_ms=70)` computes a short-time RMS envelope and positive energy flux. Peaks above a relative threshold are returned as frame indices. A minimum interval suppresses duplicate detections around one transient.

This is a lightweight onset detector, not a learned drum classifier. Threshold and interval settings should be tuned for noisy, compressed, or highly sustained source material.

### Automatic slicing

`auto_slice(audio, sample_rate, max_slices=None)` returns ordered half-open frame ranges. The first range begins at frame zero and the final range ends at the source length. Optional slice limits bound the number of regions.

`slice_audio` materializes slices from explicit frame boundaries. It preserves channel layout and does not resample or modify the source.

## 2. Break transformations

The public operations are exported from `reawarp.transforms`:

| Operation | Function | Behaviour |
|---|---|---|
| Phrase rearrangement | `rearrange_slices` | Reorders detected/explicit slices; preserves total sample count |
| Stutter | `stutter` | Repeats a selected sub-region inside its existing time slot |
| Dropout | `dropout` | Mutes seeded blocks while retaining duration |
| Reverse | `reverse_audio` | Reverses frames and preserves channel order |
| Gating | `gate_audio` | Periodic amplitude gate with short edge fades |
| Pitch shift | `pitch_shift` | Changes pitch while restoring the original frame count |
| Time stretch | `time_stretch` | Phase-vocoder duration change with approximate pitch preservation |
| Granular | `granular_resynthesis` | Rebuilds a same-length signal from overlapping jittered grains |
| Spectral freeze | `spectral_freeze` | Holds a selected spectral frame across the signal duration |

### Pipeline

`apply_break_transforms(audio, sample_rate, transforms, rng, ...)` runs operations in the exact order supplied. The pipeline copies its input, uses the caller's deterministic random stream for stochastic operations, and returns a new float32 buffer.

Supported operation names are:

`slice_rearrange, stutter, dropout, reverse, gate, pitch_shift, time_stretch, granular, spectral_freeze`.

Parameters are available on `GenerationConfig` and exposed through CLI flags. For example:

    reawarp --break-sample samples/Breaks/loop.wav \
      --break-transforms slice_rearrange,stutter,dropout,reverse \
      --break-slice-count 16 --break-stutter-repeats 4 \
      --output output/break_variation

Pitch/time/granular workflow:

    reawarp --break-sample samples/Breaks/loop.wav \
      --break-transforms pitch_shift,time_stretch,granular \
      --break-pitch-semitones 5 --break-time-stretch 1.25 \
      --break-grain-size-ms 75 --break-grain-density 1.6 \
      --output output/warped_break

The engine applies these operations only to the imported `break` sample role. Existing kick, snare, and hat overlays retain their original behaviour. The original file is read, hashed, and left untouched. Project metadata records source hash, frame counts, duration, and the ordered transformation list.

## 3. Advanced percussion synthesis

The profile catalogue is data-driven:

- 13 kick profiles: sub-focused, punch, click, soft, rubber, FM, laser, wooden, industrial, distorted, short, long-tail, and broken-digital characters.
- 6 snare profiles: acoustic, 909 crack, noise burst, tonal, industrial, and soft brush.
- 6 hi-hat profiles: closed, open, metallic, digital, noisy, and dark.

Each profile defines its own oscillator/noise balance, frequency behaviour, envelope decay, and saturation. A profile can be fixed per lane, or set to `auto` for deterministic per-hit selection. Event provenance includes the selected profile name.

## 4. Determinism and integrity

- The root seed is split into independent pattern, synthesis, and profile-selection streams.
- The break-processing chain has its own random stream.
- Stochastic operations require a caller-supplied NumPy generator.
- A transformation never mutates its input buffer.
- The original sample file is never modified.
- Transform settings and source hashes are written into project metadata.
- Stem normalization remains per-stem so one lane can be regenerated without changing unrelated rendered lanes.

## 5. Deliberate boundaries

M3 does not add a real-time DSP host, DAW transport, GUI, or mandatory native dependencies. The phase-vocoder and granular implementations are dependency-free reference implementations suitable for offline generation. They favour reproducibility and portability over the feature depth and speed of a dedicated commercial time-stretch library.

Pyo, Pippi, FluidSynth, Csound, SuperCollider, Essentia, aubio, Xenharmlib, and dataset projects remain candidates for later optional adapters. They are not required by the M3 renderer.
