# M23 — Variation browser and critical-listening workflow

**Status:** Implemented on main  
**Depends on:** M14 test/benchmark foundation, M15 stem regeneration, M17 Score provenance, M22 preview/export consistency.

## Goal

Make generation an iterative selection process while preserving determinism and user intent.

## Implementation

- reawarp.variations provides a serializable request model, immutable candidate records, candidate batches, stable content fingerprints and deterministic per-candidate seeds.
- Stem batches regenerate one or more Score roles against a frozen base. Multi-role selections are rendered as a coherent role-pair candidate. Every other stem is copied without audio processing; the service flags any unexpected change.
- Full-project/config and sample-bank batches vary the composition seed while keeping the original project as the source reference.
- Score automation batches vary existing automation trajectories around their local centre, retaining timing, lane identity, interpolation and bounds. An explicit Score patch can be supplied through the service API.
- Sound-object batches load M21 patches from the local SQLite library, render with HybridVoiceRenderer, and vary layer gain/envelope, partial gains and modulation depth. Source identity and source hashes remain fixed; processing identity, seed, transformations and renderer diagnostics are recorded. Source assets are read-only.
- The Variations workspace supports blind candidate labels, selection notes, keep/discard/promote/branch/restore, matched-level A/B, waveform and spectrogram inspection of the difference signal, and dry/processed/insert/send/return/master comparison stages. A/B buffers are analysis copies; they do not overwrite source stems or project buffers.
- Listening sets cover full mix, isolated roles, role pairs, transitions, opening/middle/ending and subtraction. Multi-item sets can be selected one excerpt at a time.
- project.export() writes a frozen base, branch base and candidate projects into candidates/, and writes listening_report.json. ReawarpProject.load() restores nested candidates and review metadata.
- SQLite project genealogy stores candidate/batch identity, direct candidate ancestry, selection state, notes, seed lineage and changed parameters. Indexed candidate stems retain the project and sound-object identity metadata.

## Determinism and invariance

A batch ID, frozen source fingerprint, request and candidate index deterministically derive a candidate seed. The saved record keeps the exact request and seed lineage so the same candidate can be recreated with VariationBatchService.generate_batch(..., batch_id=...).

For independent stem regeneration, unchanged source stem arrays remain bit-identical before file export. Export encoding is separately subject to the selected WAV bit depth. A candidate is always generated from a read-only copy of the frozen source; keep/discard/promote/branch operations update review state or the active working project, never the source project or indexed source assets.

## Listening and technical reporting

A/B copies are level-matched to a nominal -18 dBFS RMS target when peak headroom permits, with an explicit peak ceiling. If headroom is insufficient, the audition gain protects peaks and the report records whether the RMS target was reached.

Technical flags report measurable invariance, shape, finite-signal and sample-rate problems. Signal metrics are diagnostics only. There is no artistic score, ranking or automatic judgement of identity, development, role clarity, negative space, groove or taste.

Blind mode hides candidate labels and change details until the listener reveals them. The intended sequence is to listen first, write observations, then reveal parameter differences and technical flags.

## Listening protocol

Compare at matched loudness where possible. Listen for identity, development, role clarity, contrast, negative space and context. Use subtraction and role pairs to ask whether a layer is necessary or whether the arrangement works better without it. Event count, spectral magnitude and numeric metrics are prompts for questions, not a substitute for judgement.
