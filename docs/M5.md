# M5 — Universal Musical Score and MIDI Interchange

Status: implemented in the symbolic core and optional Mido adapter.

M5 creates a durable musical representation between mathematical generators and sound synthesis. It does not replace the NumPy renderer or introduce real-time scheduling. A rendered project can now be converted to a score, saved independently of its WAV stems, and exchanged with standard MIDI 1.0 software.

## 1. Design requirements carried forward

The IDM Field Guide and Advanced Composition Appendix establish the following rules:

- Musical intent is represented as events, not synthesizer callbacks.
- Musical beat time is separate from transport seconds, sample frames, and wall-clock/UI time.
- Rational beat positions avoid cumulative floating-point drift.
- Tempo, meter, and pattern/cycle length are separate concepts.
- Notes and discrete hits coexist with continuous automation lanes.
- Events retain generator, seed, source, and edit provenance.
- The exact frequency in Hz is retained even when a MIDI note number is also present.
- MIDI is an interchange format; the richer Reawarp score remains authoritative.

## 2. Score package

The public API is exported from reawarp.score and the top-level reawarp package.

### MusicalEvent

A universal event contains:

| Field | Meaning |
|---|---|
| event_id | Stable unique identity within the score |
| voice_id | Instrument, lane, or musical role |
| onset_beats | Exact rational beat position |
| duration_beats | Exact rational duration |
| kind | note, hit, grain, trigger, control, or marker |
| pitch | Fractional pitch coordinate when meaningful |
| frequency_hz | Exact positive frequency when meaningful |
| velocity | Normalized amplitude/intensity from 0 to 1 |
| articulation | Performance or envelope description |
| parameters | JSON-compatible synthesizer-independent data |
| tags | Musical role, phrase, or classification tags |
| source_id | Imported sample or source-material reference |
| seed | Generator random-stream provenance |
| channel | Optional MIDI channel |
| tuning_id | Pitch-system identity |

A score is stored as versioned JSON using the eli_lab_reawarp_score format. Beat positions and durations are written as rational strings such as "5/12", not rounded floating-point seconds.

### TempoMap and MeterMap

TempoMap supports step tempo changes and linear BPM ramps. It provides centralised beat_to_seconds and seconds_to_beat conversions. For a linear BPM ramp, conversion integrates 60 / BPM over beat position; it does not linearly interpolate elapsed seconds.

MeterMap stores time signatures independently of tempo. It provides bar_and_beat(), with one-based bar numbers and beat offsets measured in quarter-note units. A meter change begins a new bar. Pattern/cycle length is not inferred from the time signature.

### AutomationLane

Automation is a first-class score component with:

- stable target ID and unit;
- time basis: beats, seconds, or sample frames;
- ordered control points;
- step, linear, cubic, or exponential interpolation;
- optional loop length;
- optional minimum and maximum bounds;
- smoothing duration retained as playback-host metadata.

The core evaluates the curve at a requested point. It does not yet schedule those values against a live audio callback.

### Pitch and tuning

TuningSystem is a protocol with frequency_for_pitch() and pitch_for_frequency(). EqualTemperamentTuning is the built-in reference implementation. Pitch carries a pitch coordinate, exact frequency, and tuning identifier.

The event model can retain exact Hz and fractional pitch coordinates from other tuning adapters. Xenharmlib is not a dependency, and a just-intonation/regular-temperament adapter is not claimed as implemented in this milestone.

## 3. Existing generator integration

ReawarpProject.to_score() converts the existing seconds-based event records to rational beat positions using the render BPM. It maps melody events to notes and drum/sample events to hits or triggers, retaining their lane, velocity, source details, generator metadata, and seed information.

Every ReawarpProject.export() now writes:

- master.wav and aligned stems/*.wav;
- project.json and events.json for the existing render representation;
- score.json for the new universal symbolic score.

This is a conversion adapter; the original generators have not yet been rewritten to emit score-native events directly.

## 4. MIDI 1.0 adapter

Mido remains optional and is imported only when MIDI functionality is requested.

Supported import/export data:

- Note-on/note-off events and channels.
- Tempo events and time signatures.
- MIDI Control Change messages mapped to automation targets named midi.cc.<channel>.<controller>.
- Reawarp text metadata for exact event values, fractional pitch, frequency, tuning ID, event identity, tags, and custom automation.
- Type-1 multi-track MIDI files.

Use the Python API:

    score.export_midi("composition.mid")
    imported = Score.from_midi("composition.mid")
    imported.save("composition.json")

Or use the command-line tools:

    reawarp-midi-import composition.mid --output composition.json
    reawarp-midi-export composition.json --output composition.mid --ppq 960

A new render can directly export MIDI:

    reawarp --bpm 137 --duration 12 --seed 211 \
      --output output/render --midi-output output/render.mid

### Interchange limitations

Standard MIDI 1.0 note numbers are integer semitones. Reawarp rounds fractional pitches to the nearest integer note for conventional playback. Exact pitch, frequency, event ID, and Reawarp event data are embedded in text meta events; software that strips unknown text metadata will not preserve those extensions.

MIDI tempo maps do not represent a continuous mathematical BPM ramp. Reawarp approximates linear ramps using discrete tempo events at the requested sampling interval (default one quarter-note subdivision of a beat, i.e. 1/4 beat). A Reawarp re-import therefore receives a step approximation of that ramp.

MIDI 2.0, MPE authoring, SysEx device profiles, and OSC transport protocols are outside M5.

## 5. Dependency and compatibility boundaries

- The base score model uses only the Python standard library.
- mido>=1.3 is in the optional midi extra.
- music21 remains an optional theory-analysis tool, not a runtime requirement for score editing.
- Xenharmlib remains a future tuning adapter candidate.
- The core score layer does not import Qt, SoundDevice, librosa, or FluidSynth.

Install the score/MIDI development environment:

    python -m pip install -e ".[dev,audio,midi]"

## 6. Deliberate boundaries and next work

M5 does not yet include:

- a score editor or piano-roll UI;
- score-driven synthesis/rendering using tempo maps or automation;
- a live event scheduler or MIDI device output;
- a complete just-intonation/regular-temperament library;
- MIDI 2.0 or MPE editing.

M5.1 refines the sound palette and rhythmic integrity of the renderer: phrase-based break grammars, transient-sliced sample playback, profiled additive/FM melody voices, and a separate harmonic ambience stem. See [M5.1.md](M5.1.md).

The next useful milestone is M6: searchable sample/stem library, metadata indexing, collections, similarity descriptors, and variation genealogy. M6 can consume the stable IDs, tags, source references, slice metadata, tuning IDs, and provenance established here.
