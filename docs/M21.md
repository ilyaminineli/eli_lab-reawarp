# M21 — Sound-object and hybrid instrument architecture

**Status:** Partially implemented — versioned sound-object schema, deterministic hybrid renderer, modal/additive voices, typed controls and library lineage. Editor UI and target-machine listening/performance sign-off remain future work.

**Depends on:** M17 Score renderers and M18 musical automation; benefits from M20 perceptual orchestration.

## Implemented architecture

### 1. Sound-object patch schema

`reawarp.synthesis.sound_object.SoundObjectPatch` is a versioned JSON-compatible instrument description. It separates:

- `source_identity_id`: the material or source character being retained.
- `processing_identity_id`: the synthesis/processing construction applied to that material.
- `sources`: asset-backed references with indexed SHA-256 identity, or named procedural sources.
- `layers`: transient, body, tail, texture or voice roles with exact integer frame spans, source offsets, independent gain/pan/envelope and identity tags.
- `pitch_model`, `spectrum`, `modulation` and `spatial`: editor-facing, validated parameter groups.
- `transformations`: deterministic operation, seed, parameter record, source/output hashes and explicitly preserved/changed identity dimensions.

Envelope times are seconds; pitch frequencies are Hz; layer positions are frames at the patch sample rate; modulation depth is normalized; pan is -1..1; stereo width is 0..2. Asset-backed source references are validated against the local library's asset ID and file digest when saved. Procedural sources declare a model rather than pretending to have an external asset hash.

The public dataclasses provide `to_dict()` and `from_dict()` for patch editing and interchange. A graphical patch editor is not part of this iteration.

### 2. Hybrid frame renderer

`HybridVoiceRenderer.render(patch, source_audio)` accepts immutable source arrays keyed by source ID and returns:

- `audio`: the summed stereo render after transparent peak-ceiling compensation.
- `layers`: each isolated layer at its exact declared frame position, for solo audition.
- `diagnostics`: pre/post peak, pre-compensation clipped sample count, applied headroom gain, mono-fold level difference, phase-correlation warnings and estimated output-array memory.

Mono sources are equal-power panned; stereo sources retain mid/side structure with explicit width and pan. Layer delays, source offsets, gain and envelope are independent. The renderer validates finite samples and matching sample rates; it never silently resamples or mutates source buffers. A requested pitch shift resamples into a fixed layer frame span, padding the non-overlapping remainder rather than changing the Score/object timeline.

Phase-correlation and mono-loss reports are review prompts, not quality scores. Headroom reduction is explicit in the diagnostics; it is not hidden clipping or a limiter preset. Returned layer stems are pre-master layer renders; the summed `audio` field is the post-headroom result.

### 3. Selected native voice families

Two NumPy-only voice families are included:

- `render_modal_resonator_bank`: seeded modal oscillators with independent frequencies, amplitudes, attacks and decay times. Use for metallic, bell-like and inharmonic resonant bodies.
- `render_additive_partial_voice`: a harmonic/inharmonic partial set with independent gain and decay. Use when spectral-envelope evolution matters more than a single oscillator/filter path.

Both are deterministic for a fixed application version, inputs and seed; both enforce Nyquist and finite parameter bounds. They are opt-in utilities, not replacements for existing synthesis palettes. Wavetable, scanned/pulsar, granular-cloud and neural synthesis are not added here.

### 4. Typed Score control targets

`sound_object_automation_targets(patch)` returns patch-scoped `AutomationTarget` definitions and `register_sound_object_automation_targets(registry, patch)` registers them in an existing registry. Current consumed targets are:

| Target ID suffix | Unit / range | Effect |
|---|---|---|
| `gain` | normalized, 0..4 | object output gain |
| `pitch` | semitones, -48..48 | layer source pitch shift, exact frame span retained |
| `attack`, `decay`, `release` | seconds, 0..30 | layer ADSR overrides |
| `modulation.rate` | Hz, 0..40 | coherent object LFO |
| `modulation.depth` | normalized, 0..1 | coherent object LFO depth |
| `spatial.pan` | normalized, -1..1 | object pan |
| `spatial.width` | ratio, 0..2 | stereo width |
| `layer.<layer_id>.gain` | normalized, 0..4 | independent layer gain |

The standalone renderer accepts a `control_values` mapping keyed by those exact IDs. This makes controls registry-addressable and testable; a full GUI automation editor and automatic multi-object ScoreRenderer integration are not claimed in this scope.

### 5. Non-destructive resampling and library lineage

`resample_audio_non_destructive` returns a new buffer and a `TransformationRecord` containing source/output hashes, rate/frame changes, seed and identity dimensions preserved/changed. Input arrays are read-only from the function's perspective.

The SQLite `SampleLibrary` now has additive `sound_objects` and `sound_object_variants` tables:

- `save_sound_object` validates a patch and any indexed source asset hash.
- `get_sound_object` and `search_sound_objects` retrieve patches by name, tags and separate identity IDs.
- `record_sound_object_variant` attaches an indexed rendered audio asset to its patch with seed, source hashes and transformation history.
- `sound_object_variants` returns the asset hash and existing audio descriptors as well as its lineage.

The migration is additive (`CREATE TABLE IF NOT EXISTS`) and leaves existing audio assets, collections and project genealogy intact. A rendered WAV is indexed through the existing `index_file` path with `asset_type="sound_object_variant"`, then attached to its patch.

## Example

```python
import numpy as np
from reawarp.synthesis.sound_object import (
    HybridVoiceRenderer,
    SoundObjectLayer,
    SoundObjectPatch,
    SoundObjectSource,
)

sample_rate = 48_000
frames = sample_rate
patch = SoundObjectPatch(
    patch_id="bronze-impact",
    name="Bronze impact",
    sample_rate=sample_rate,
    seed=211,
    source_identity_id="source:bronze-strike",
    processing_identity_id="process:modal-body-tail",
    sources=(
        SoundObjectSource(
            "body-source", source_kind="procedural",
            sample_rate=sample_rate, source_model="modal-bank",
        ),
    ),
    layers=(
        SoundObjectLayer("body", "body", "body-source", 0, frames),
    ),
)
t = np.arange(frames) / sample_rate
source = np.sin(2 * np.pi * 440 * t).astype(np.float32)
result = HybridVoiceRenderer().render(
    patch, {"body-source": source},
    control_values={"sound_object.bronze-impact.gain": 0.45},
)
solo_body = result.layers["body"]
summed = result.audio
print(result.diagnostics)
```

## Performance and listening validation

A reproducible benchmark harness is provided:

```bash
python scripts/benchmark_sound_objects.py --durations 1 5 30 --sample-rates 22050 48000 --output benchmark-m21.json
```

It records per-family render time, real-time factor, output bytes, Python-traced peak allocation, signal peak and hybrid diagnostics. NumPy output buffers are reported separately because Python allocation tracing does not account for every native array allocation. These measurements should be collected on the target machine before any new voice becomes a default. No existing default is changed in M21.

Automated tests cover schema ranges/source references, exact frame spans, source immutability, layer solos and sum, deterministic modal/additive output, phase-cancellation warnings, mono/headroom diagnostics, typed controls, resampling hashes and SQLite patch/variant lineage.

Subjective matched-level listening has not been performed by CI. Before sign-off, compare source, transient, body, tail and sum solo/in-context; check mono and low-volume playback; audition dense role combinations; record target-machine CPU and peak-memory results. These remain experimentally unverified.
