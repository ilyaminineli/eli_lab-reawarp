# M21 — Sound-object and hybrid instrument architecture

**Status:** Planned  
**Depends on:** M17 Score renderers and M18 musical automation; benefits from M20 orchestration.

## Goal

Create reusable instruments around sound-object behaviour: source identity, envelope, spectrum, modulation, space and transformation.

## Philosophy

The sound-design guide describes a sound as a designed object whose attack/body/tail, spectral envelope, modulation, spatial character and processing identity can be developed independently. Hybrid layers should have complementary jobs and fuse perceptually when desired.

## Scope

1. **Sound-object schema**
   - Source material(s), source identity, pitch/resonance model, transient/body/tail roles, envelope, spectrum, modulation, spatial intent and transformation history.
   - Store source identity separately from processing identity.
   - Version parameters and record deterministic seeds/provenance.

2. **Hybrid instrument roles**
   - Reusable transient/body/tail combination model for percussion and pitched voices.
   - Independent source gain, envelope and time alignment.
   - Phase and mono-compatibility checks where sources are correlated.
   - One object may have multiple layers; one layer may intentionally serve more than one object.

3. **Advanced voice families selected by use-case**
   - Modal/resonator banks, additive partial envelopes, wavetable/scanned/pulsar-like synthesis and granular spectral clouds.
   - Choose only a small subset where a composition needs a distinct behaviour.
   - Keep optional dependencies optional and native integrations lazy.

4. **Modulation and identity**
   - Coherent modulation of related parameters.
   - Stable invariants across sound-family variants.
   - Score automation can address object parameters by typed target ID.
   - Resampling is an explicit non-destructive transformation with lineage.

5. **Library integration**
   - Store sound-object patches and rendered variants as searchable library items.
   - Preserve asset hashes, source references, features and transformation lineage.

## Explicitly out of scope

Implementing every synthesis method in the guide, a plug-in host or an opaque neural-synthesis runtime.

## Acceptance criteria

- Sound-object schema validates units, ranges and source references.
- Every voice uses deterministic seed derivation and exact frame spans.
- Hybrid roles can be auditioned individually and together.
- No unexpected phase cancellation/clipping; mono and stereo paths are tested.
- Variants preserve declared identity dimensions and record transformations.
- Performance/memory cost is benchmarked before enabling any new default voice.

## Listening protocol

Compare source, transient, body, tail and summed object at matched level, first solo then in context. Test mono, low volume and a dense role combination. Judge whether it reads as one intended object, has useful identity, and contributes a distinct role.

## Deliverables

- Sound-object data model and editor-facing representation.
- A reusable hybrid voice renderer.
- One or two carefully selected advanced voice families.
- Patch/variant library integration.
