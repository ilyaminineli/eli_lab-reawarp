## Musical purpose

Spectral delay gives different frequency regions different rhythmic memories. A click, metallic hit, vocal fragment or percussion stem can leave low, mid and high-frequency trails with different delay intervals and decay rates. The direct transient remains intact while the spectral components unfold as a secondary rhythmic object.

A useful arrangement example is a sparse metallic percussion role: the low body repeats slowly, mid resonances answer at a shorter interval, and high ticks scatter later. The high-frequency trail must not erase the next kick or snare. Keep the dry source available for comparison.

## Algorithm

The offline engine uses a centered STFT with a periodic Hann window and weighted overlap-add reconstruction. Frame size is a power of two from 256 to 8192; hop divides the frame size and is no larger than half of it. Frequency bands are explicit, non-overlapping ranges. Each FFT bin receives at most one band's delay, feedback and gain; unassigned bins remain direct.

For bin (k) and STFT frame (m):

[
Y_{k,m}=X_{k,m}+g_k a_k Y_{k,m-D_k}
]

(D_k) is the band's delay rounded to an integer hop count, (a_k) is feedback (0–0.85), and (g_k) is repeat gain (0–1.5). A zero delay disables the recursive tap for that bin. This is a fixed and inspectable delayed recurrence, not a user-defined feedback graph or FDN.

Positive spectral flux estimates abrupt attacks. `transient_preserve` (0–1) attenuates only the repeat contribution on those frames; the direct input spectrum is never attenuated by this detector. It is a restrained repeat safeguard, not a general transient shaper.

## API and parameters

`reawarp.dsp.spectral_delay.spectral_delay(audio, sample_rate, *, frequency_bands=None, frame_size=1024, hop_size=256, feedback=0.35, wet=1.0, transient_preserve=0.25, max_tail_seconds=12.0, bypass=False)` returns `SpectralDelayResult(audio, diagnostics)`.

Each `frequency_bands` entry has:
- `low_hz`, `high_hz`: half-open band edge in Hz; the last Nyquist bin is included when the band reaches Nyquist.
- `delay_ms`: 0–2000 ms; positive delays are quantized to at least one STFT hop.
- `feedback`: optional per-band value 0–0.85, otherwise the function-level value.
- `gain`: optional linear repeat gain 0–1.5, default 1.

With no band list the whole spectrum receives a 180 ms delay. Gaps are allowed; overlaps are rejected. Sample rate must be an integer of at least 1 kHz. Mono and stereo are processed independently with no crossfeed. Input frame count and channel layout are preserved before the explicit rendered tail.

## Tail, latency and safety

Centered offline reconstruction aligns output sample zero to the source origin, so reported file-alignment latency is zero. This is not a real-time streaming callback latency guarantee. The theoretical repeat count is estimated to decay below -80 dB using the highest active feedback; the longest active delay sets the estimate. `max_tail_seconds` (0–30 seconds) caps the rendered extension and diagnostics state when that cap truncates the estimate.

No limiter, normalization, auto gain, hidden dry duplication or denormal flushing is applied. Bypass and `wet=0` return exact-length dry copies. Inputs are not mutated. Diagnostics report the band map, quantized delays, maximum feedback, estimated repeats, tail/truncation, processing time, working-buffer estimate, peak/RMS/headroom, finite-output state and output bytes.

## Dependencies, benchmark and listening

NumPy only; no SciPy, Pyo, GPU or native DSP runtime. The shared `reawarp.dsp._stft` helpers are internal to M24 and do not alter M22 routing.

Run:

```bash
python scripts/benchmark_m24_2_spectral_delay.py --duration 5 --sample-rate 48000 --output m24-2-benchmark.json
python scripts/render_m24_2_listening_example.py --output output/m24-2-spectral-delay
```

The benchmark records Python/NumPy/platform, wall time, real-time factor, tracemalloc peak and engine diagnostics. The listening generator writes dry, RMS-matched processed and unmatched processed audio plus a JSON report. Matching is for audition only and never changes the processor's gain.
