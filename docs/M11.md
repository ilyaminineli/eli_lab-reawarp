# M11 — Editable FX Chains

## Intent

M11 turns the fixed M10 starter chains into a user-authorable serial processing workflow. The design follows the sound-design guide's processing-order and gain-staging sections:

- Stage order changes the sound; it is always visible and editable.
- Each stage exposes the parameters that materially shape its result and a local wet/dry mix.
- The global wet/dry control remains a separate parallel blend against the original source.
- A dry reference is retained; render results are invalidated when chain settings change.
- Chains are saved as portable, versioned JSON and can be reused from the GUI or CLI.
- Parameter ranges are bounded. The renderer clamps filter cutoffs to the usable Nyquist region for the source sample rate.

The implementation remains non-destructive and offline. It does not attach effect processing to the real-time audio callback or change generated stems.

## Implemented stage types

| Stage | Parameters | Reawarp backend |
|---|---|---|
| High-pass | Cutoff, stage mix | Pyo `ButHP` |
| Low-pass | Cutoff, stage mix | Pyo `ButLP` |
| Band-pass | Centre frequency, Q, stage mix | Pyo `ButBP` |
| Saturation | Drive, slope, stage mix | Pyo `Disto` |
| Delay | Delay time, feedback, stage mix | Pyo `Delay` |
| Reverb | Room size, damping, stage mix | Pyo `Freeverb` |
| Frequency shift | Shift in Hz, stage mix | Pyo `FreqShift` |

All stage types use a bounded local mix. The chain itself is serial: the output of one stage feeds the next stage. The global wet control blends the final processed signal against the original source.

## Desktop workflow

1. Open **FX LAB** and load a mono/stereo audio source.
2. Select a starter chain or choose **CUSTOM CHAIN**.
3. Add, remove, and reorder stages in the visible stage list.
4. Select a stage and edit its parameters. Each edit invalidates the previous render.
5. Set the global wet/dry blend and tail allowance.
6. Render and compare the processed waveform/spectrogram against the dry reference.
7. Save the chain JSON for reuse, audition either signal, and export the processed result as a new WAV.

The starting chains remain available: `restrained_space`, `tape_echo`, `metallic_machine`, and `digital_fracture`.

## Portable chain format

Schema version 1 uses the following structure:

```json
{
  "schema_version": 1,
  "name": "metallic_echo",
  "wet": 0.72,
  "tail_seconds": 2.0,
  "stages": [
    {"type": "bandpass", "center_hz": 1850.0, "q": 2.7, "mix": 0.6},
    {"type": "frequency_shift", "shift_hz": 13.0, "mix": 0.18},
    {"type": "delay", "delay_seconds": 0.047, "feedback": 0.14, "mix": 0.2},
    {"type": "reverb", "size": 0.35, "damping": 0.55, "mix": 0.18}
  ]
}
```

The file is self-contained and does not store audio. Unknown stage names, unsupported schema versions, invalid numeric values, excessive feedback, and oversized chains are rejected before rendering. A chain contains between 1 and 12 stages.

The CLI renders the same format as the desktop workspace:

```powershell
reawarp-fx input.wav output.wav --chain-json metallic_echo.json
reawarp-fx --validate-chain-json metallic_echo.json
reawarp-fx --list-stages
```

A starter preset can still be rendered without a JSON chain:

```powershell
reawarp-fx input.wav output.wav --preset tape_echo --wet 0.70 --tail 2.0
```

## Dependency and compatibility policy

Pyo remains in the isolated optional `pyo` extra. The editor and CLI can list stage types and validate chain JSON without loading Pyo; actual audio rendering requires the Pyo and SoundFile packages.

The NumPy composition renderer, MIDI score model, local audio library, and stem generator remain independent from this FX backend.

## Validation

GitHub Actions compiles the package, smoke-renders the normal generator, checks the FX preset and stage registries, validates a small custom chain JSON file, checks the local library CLI, and imports the desktop entry point on Python 3.10–3.12.

No unit-test suite is recreated. Actual Pyo sound rendering and musical audition still need to be checked on Windows with the installed Pyo build and the user's audio interface.

## Deliberately deferred

- Effect inserts and pre/post sends for individual generated stems.
- Tempo-synchronised delay division and project BPM/tempo-map integration.
- Parallel, multiband, and feedback routing with explicit headroom/phase management.
- Convolution reverb, spectral delay, cross-synthesis, and oversampled nonlinear stages.
- Automation lanes, modulation routing, sidechain interaction, and VST hosting.
