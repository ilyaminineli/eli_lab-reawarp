# M4 — Reawarp Desktop Instrument

Status: first usable desktop instrument implemented.

M4 turns the offline generation engine into a compact, laboratory-style Windows desktop application. It is intentionally not a general-purpose DAW. The generator remains usable through Python and the CLI without importing PySide6, PyQtGraph, or SoundDevice.

## 1. Product identity distilled from the design documents

Reawarp is a mathematical sound laboratory and a collaborator for generating, auditioning, selecting, and recomposing musical material.

The reference documents establish these principles:

- **Musical intent is data.** Events and generator provenance describe what should happen; the renderer decides how it sounds.
- **Time domains remain separate.** Musical time, transport time, sample-frame time, and wall-clock/UI time must not be conflated. The interface timer displays transport progress; it does not drive synthesis timing.
- **The grid is a coordinate system, not a prison.** Generators may use a step grid and controlled timing variation, while audio analysis and preview remain sample-frame based.
- **Algorithms behave like collaborators.** The composer constrains and explores, listens, chooses, edits, and freezes material rather than delegating the entire composition to uncontrolled randomness.
- **Musical roles matter more than track count.** The interface exposes meaningful global parameters, generator modules, sound profiles, sample transformations, and stem controls.
- **Repetition needs contrast.** Generated material remains reproducible and independently mutable so a successful layer can be kept while another is regenerated.
- **The application is offline-first.** Rendering and analysis happen outside the audio callback. The callback only copies pre-rendered audio.
- **Source material is non-destructive.** Imported samples are read and transformed in memory; Reawarp never overwrites the source file.

## 2. Workspaces proposed in the project discussion

| Workspace | Responsibility |
|---|---|
| Generator | Global constraints, module enablement, one-click generation |
| Drum Lab | Kick design and break manipulation |
| Sequence Lab | Mathematical melodic patterns |
| Geometry Lab | Visual geometric generators |
| Synthesis Lab | Instrument and parameter design |
| Sample Lab | Import, transient analysis, and slicing |
| Stem Mixer | Volume, pan, mute, solo, regeneration, and export |
| History | Generated versions and variation genealogy |

The M4 first iteration implements the end-to-end path through Generator, Break Lab, and Stem Mixer. The other specialist workspaces remain follow-on work, not empty tabs pretending to be finished features.

## 3. Implemented M4 scope

### Generator
- BPM: 60–220.
- Duration: 5–20 seconds.
- Complexity: 0–1.
- Integer or text seed, with a new-seed control.
- Melody, noise texture, and harmonic ambience enable/disable controls.
- Five profiled additive/FM melody voices.
- Fixed or weighted deterministic automatic kick/snare/hi-hat profile selection.
- Break rhythm grammar controls: style, event density, phrase variation, and cycle length.
- Optional imported break sample.
- Background loop generation so the interface remains responsive.
- Master and per-stem audition selection.

### Break Lab
- Import an audio sample.
- Display waveform and spectrogram.
- Analyze transient boundaries and display them over the waveform.
- Configure the M3 transform chain and key parameters.
- Serialize settings into GenerationConfig and process the imported break through the offline engine.
- Keep imported source files untouched.

### Stem Mixer
- List generated stems.
- Per-stem gain, pan, mute, and solo.
- Per-generator regeneration for kick, snare, hats, synthetic break, melody, noise texture, and ambience.
- Apply mixer controls to audition and exported master, with coalesced preview refreshes and live buffer replacement during playback.
- Keep individual stem WAV files as the original aligned render buffers.
- Export 24-bit WAV stems, mixer-adjusted master, project/event metadata, and separate mix settings JSON.
- Preview refresh is debounced while controls move, avoiding repeated full spectrogram analysis for every slider tick.

### Transport
- SoundDevice output-device selection.
- Play, pause/resume, and stop.
- Playback reads a completed float32 stereo buffer.
- The PortAudio callback does not generate, transform, load, or write audio. Mixer updates are prepared on the GUI thread and swapped at the next callback block boundary; the transport position is preserved.

## 4. Internal architecture

```text
PySide6 Main Window
  ├── Generator controls
  ├── Break Lab / transient preview
  ├── Stem Mixer / export
  └── Waveform + Spectrogram
          |
          v
      RenderWorker (QThreadPool)
          |
          v
      ReawarpEngine
       ├── GenerationConfig
       ├── deterministic random streams
       ├── pattern and melody generators
       ├── M3 sample transformation chain
       └── synchronized ReawarpProject stems
          |
          +------> AudioPreview
          |
          +------> AudioPlayer -> SoundDevice / PortAudio
          |
          +------> WAV + JSON export
```

The desktop layer is an optional client. Importing `reawarp` or using `reawarp.cli` does not import the Qt stack.

## 5. Regeneration and sample integrity

A user may keep a kick and melody while regenerating the break layer. The selected generator receives variation seeds; unrelated rendered buffers must remain bit-identical.

Imported sample overlays also have a baseline trigger score. Regenerating a procedural kick or break must not silently change separate `sample_kick` or `sample_break` stems. Sample-overlay trigger patterns and break processing use the unvaried root streams; the procedural lane uses the requested variation streams.

This makes an imported sample overlay an independent, reproducible layer that can be retained while its related procedural voice changes.

## 6. Dependencies and installation

The minimal package remains NumPy-only. M4 dependencies are grouped in the `m4` extra:

- PySide6 — Qt desktop widgets and application lifecycle.
- PyQtGraph 0.14.x — waveform and spectrogram rendering.
- SoundDevice — PortAudio playback and output-device access.

PyQtGraph is capped below 0.15 for this release line to retain Python 3.10 support. PySide6 is capped below 6.12 because 6.12.0 has a confirmed signal-emission reference-counting bug on CPython 3.10 and 3.11 that can abort the process with `bool_dealloc`; Qt tracks it as [PYSIDE-3474](https://qt-project.atlassian.net/browse/PYSIDE-3474), with 6.12.1 listed as the fix version. The 6.11.3 release is the newest available safe line in this pin. Revisit the cap once a corrected release is available and verified across the supported Python matrix.

Install the development and runtime set:

    python -m pip install -e ".[dev,audio,m4]"

Start the application:

    reawarp-gui

or:

    python -m reawarp.ui

The earlier `.[dev,audio]` command installs the CLI/core audio tools only. It does not request the desktop or playback dependencies.

If upgrading an environment that previously installed PySide6 6.12.0, pip may leave the separate `PySide6-Pdf` and `PySide6-WebEngine` 6.12 extension distributions behind after downgrading the main Qt packages to 6.11.3. Remove those stale optional distributions and verify the environment:

    python -m pip uninstall -y PySide6-Pdf PySide6-WebEngine
    python -m pip check

The PDF and WebEngine modules are not used by Reawarp's desktop interface.

## 7. Deliberate boundaries and next work

M4 is an offline generator and stem audition tool, not yet a live instrument or full DAW. It does not implement a real-time event scheduler, arrangement timeline, MIDI, scene director, plug-in host, note editor, or sample-accurate transport seeking.

M5 establishes the universal musical-event/score representation, rational beat time, tempo maps, automation events, tuning interface, and MIDI interchange; see [M5.md](M5.md). M5.1 hardens the sound palette and break sequencing; see [M5.1.md](M5.1.md). M6 can now develop the searchable stem/sample library and variation genealogy. Real-time scheduling and external synthesis backends must not be added to the M4 audio callback.
